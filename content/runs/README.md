# content/runs: kinds of run

A run is defined as data (run generation, docs/milestones/run-generation.md): a run definition says which features the run has, and the game generates the complete run from it and the content there is (a biome's map, connected biomes CB8), so no chain of rooms is made by hand. One file per kind of run, `<id>.tres`, a `RunDefinition` (`core/base/run_definition.gd` documents every field); the registry finds it by its `id` under `runs`.

## Contract

- **Its biomes** (`biomes`), in order, each a `MapRules` (`core/base/map_rules.gd`) of its own: the biome (`biome`, as rooms and enemies name it), which kinds of room may stand where (`kinds`), what a fight room's enemies cost at most together (`room_budget`, before the run's scaling), and how they come in (`spawning`, a `SpawnRules`, `core/base/spawn_rules.gd`; enemy spawning EA4): in groups of `group_share` of the room's scaled budget by cost, the next when the cost still standing drops to `refill_share` of it (below `group_share`), the bodies of a group `stagger` seconds apart; none: the whole list at once. One biome for now.
- **A biome's map** (connected biomes, docs/milestones/connected-biomes.md; `BiomeGenerator`, gameplay/run/README.md): every room of the biome stands at its place in one world, joined by bridges. The `MapRules` say how many rooms it holds (`rooms_min`, `rooms_max`, the start room and the bridges not counted; both 0: the start room alone, `start_only`, a test's pinned room), its start room's kind (`start_kind`, `start`), how many fights lie on every way to the boss at least (`fights_on_way`), the depth its scaling per depth reaches its end at (`scale_depth`; deeper rooms keep it), and its shapes (`styles`, each a `MapStyle`, `core/base/map_style.gd`: `id`, `weight`, `way_share`, `branch_chain`, `hub_pull`, `loops`, `loop_pull`).
- **The kind table** (`kinds`, `KindRule`, `core/base/kind_rule.gd`): one line per kind of room (a `RoomKind` id, content/room_kinds), read by depth (bridges from the start room: `first_row`, `last_row`; below 0 counts from the deepest, -1 the deepest itself, the boss's line, which `first_row` and `last_row` -1 make the way's end), its `weight` against the other kinds, `least` (rooms of it in every biome: the fixed kinds), `chance` (of each room past `least` up to `max_per_run`: the chance kinds; 0 is no limit), `dead_end` (one bridge in, none on), the kinds that may not lead to it (`not_after`) and whether the run needs it (`required`). The rest of the rooms are the lines with no `max_per_run`, by `weight`.
- **Its scaling** (`scaling`, a `RunScaling`, `core/base/run_scaling.gd`; run generation RG5): how much harder each room is, a curve per depth (`per_depth`: its `start` at the start room, its `end` at the rules' `scale_depth`) times one per extra player (`per_player`: its `start` with one player, its `end` with four), each a `ScaleCurve` (`start`, `end`, `easing`: 1 evenly, above 1 most of the change early, below 1 late, as a card's speed curve). The scale multiplies a fight room's `room_budget` and every enemy's and boss's health (gameplay/difficulty); none: the same everywhere.
- **Nothing names a room or an enemy:** the rooms of a biome are the templates that name it and host a kind (`RoomBase.biome`, `kinds`) with a socket (`RoomSocket`, content/rooms), its bridges its walkways, its enemies the enemies that name it (`EnemyBase.biomes`, `cost`, `min_depth`), its bosses the bosses that do. New content joins every run of its biome by being added, and deleting it touches no run.
- `RunDefinition.biome_problems(content, shapes)` names what keeps a map from being made from the content there is (the templates' shapes from `Registry.piece_shapes(biome)`; `Registry.run_problems(id)` asks it for a run by id); `Registry.validate_runs()` runs it on every run (warned at start in a debug build), and `tests/content/runs/test_runs.gd` holds it empty. The rules' own checks, on made-up content: `tests/core/test_run_rules.gd` and `tests/gameplay/run/test_biome_generator.gd`. (The row map's depth, width and branches, `max_per_row` and its validator went with connected biomes CB8.)

## Allowed files

`.tres`, plus `.uid` and `.license` files. Limit: 1 MB per file.
