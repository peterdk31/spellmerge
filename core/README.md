# Core

## Purpose

The shared services every other area stands on: the event bus, the content registry, input, per-player UI focus, saving, base classes, the projectile manager and object pools. Gameplay, HUD and content build on it; it builds on nothing of theirs.

**Closed to outside PRs.** Claude maintains `core/` alone. An outside PR touching it is closed with "open an issue": describe the problem or the missing hook there, and Claude decides how `core/` should change.

## Contract

- **Dependency direction:** `core` ← `gameplay` ← `content`. `core/` depends on none of `gameplay/`, `hud/` or `content/`. It finds content by folder through `core/registry`.
- **Sub-folders, one per service:**
  - `events/`: the event bus (`spell_cast`, `enemy_died`, `player_downed`, `room_cleared`, ...). One autoload, `Events` (`events/events.gd`), with a typed signal per event and the player index first. Areas talk only through it. It owns the event definitions; each area's README lists only which events the area sends and listens to.
  - `registry/`: discovers content by folder, so no central list is edited. One autoload, `Registry` (`registry/registry.gd`), scans `content/` and `audio/` when the game starts (`scan()` again with other roots, for tests). `get_resource(folder, id)`, `get_ids(folder)`, `get_all(folder)` and `get_folders()` answer by folder (`spells`, `enemies`, `rooms`, ... the direct children of `content/`) and id; every `.tres` below a folder that has an `id` is registered, at any depth, and the first file in sorted path order wins a duplicate id (with a warning). The `demo` flag: with `demo_only` on (set from the `demo` feature tag) resources whose `demo` is false are hidden from every question. `validate_spells()` runs the spell validator on everything under `spells` and the reaction table (and in a debug build the registry pushes a warning per problem at start). `get_sound(id)` returns the `.ogg` under `audio/` whose file name is the id, or `null` when there is none; gameplay and feel ask for a sound by id and play nothing on `null`, so a missing sound is silent and never an error. It is the only script that loads from a computed path; everyone else uses literal `load("res://...")` or `preload(...)`.
  - `input/`: one autoload, `PlayerInput` (`input/input_manager.gd`); devices join with a button press and each player gets their own device. A gamepad takes the lowest free index; the keyboard and mouse only take P1 (index 0), so P2–P4 are gamepads. The `leave` action or an unplugged gamepad frees the slot. Bots add a virtual device per index (`add_virtual_device`, `send_virtual`) that goes through the same `handle_event` path as real input. Gameplay asks by player index (`get_move`, `is_action_pressed`, `is_action_just_pressed`) and never reads `Input` itself (call `is_action_just_pressed` only from `_process` or `_physics_process`). Each physical input is tracked on its own and an action takes the strongest, so releasing one of two held inputs does not cancel the other. The actions (`move_left`, `move_right`, `move_up`, `move_down`, `dodge`, `cast`, `overlay`, `swap` (Q or left shoulder: switch the prepared spell), `join`, `leave`) are in `project.godot`. Aim: `get_aim(player)` is the right stick as a unit vector (zero in the dead zone; `send_virtual_aim` for bots) and `is_mouse_aiming(player)` is a flag for the keyboard player (a mouse move or click sets it, the keyboard `cast` key clears it); the wizard turns the mouse into a direction because that needs the world. It sends `device_joined` and `device_left`; `coop` turns them into `player_joined` and `player_left`. `set_captured(player, true)` hides a player's move, `cast`, `dodge` and `swap` from those gameplay questions (`overlay` stays) while their UI panel is open, so gameplay needs no check of its own; `get_press_count` counts presses and is never captured, so UI code loses no quick tap.
  - `ui_focus/`: per-player UI focus, because Godot has one global focus. One autoload, `UIFocus` (`ui_focus/ui_focus.gd`). `open(player, controls)` gives a player a panel; only that player's input (through `PlayerInput`) moves it: up/left and down/right step through the controls, `cast` activates, `dodge` cancels (presses come from `get_press_count`, so a quick tap is not lost). An open panel captures its owner's gameplay input through `PlayerInput.set_captured`, so their wizard does not walk, cast or dodge meanwhile; opening needs a joined device. A focused control that gets disabled, hidden or freed loses focus and is never activated. It has its own signals (`opened`, `closed`, `focus_changed`, `activated`, `cancelled`, player index first); a widget checks that the player is its owner. It never calls `grab_focus`, never pauses, and closes a panel when its player's device leaves. Every widget builds on it.
  - `save/`: reading and writing under `user://` only.
  - `base/`: base classes (`enemy_base.gd`, `room_base.gd`: small M1 resources with `id` and `demo`) and build info. M2's spell components (part 1) are `spell_component.gd` (`SpellComponent`: `id`, `demo`, `display_name`, `complexity` 1–4, `icon`, `kind()`, `ranges()` and `range_problems()`) and its four kinds `form_base.gd` (`FormBase`), `element_base.gd` (`ElementBase`), `modifier_base.gd` (`ModifierBase`) and `trigger_base.gd` (`TriggerBase`), each documenting its fields and allowed ranges; the element reactions are `reaction_table.gd` (`ReactionTable`, `find(status_id, element_id)`) of `reaction_row.gd` rows (`content/spells/reactions.tres` holds six reactions as twelve rows, one per direction), which have no `id`, so the registry never takes them for content. M1's `SpellBase` is gone (M2 part 11): the one way to fire is `Spells.cast(player, slot, origin, direction, mana)`, which returns the mana spent or `REFUSED`. Players and bots call it and read no spell field; `tests/core/test_spell_field_reads.gd` fails when a script outside `content/spells/`, `core/base/` and `core/spells/` does. `build_info.gd` holds the build info.
  - `spells/`: `validator.gd` (`SpellValidator`, M2 part 9) checks components and the reaction table and returns problems as rule, file, field and fix (`check_all`, `check_component`, `check_reactions`, `format`); the registry runs it, `tests/content/spells/test_validators.gd` fails on any problem. The spell runtime (M2) is one autoload, `Spells` (`spells/spells.gd`). It compiles recipes (part 5), casts them and runs their triggers (part 6). `compile(recipe)` turns a recipe (a Dictionary of component ids: `form`, optional `element`, `modifiers`, `trigger`, and `held`, a recipe of the same shape) into a `CompiledSpell` (`compiled_spell.gd`: final damage, mana, cooldown, speed, radius, shots, pierce, homing turn, chain jumps, trigger, the held spell, complexity, a plain `description`). It never errors: a recipe that breaks a rule (no form, unknown id or wrong kind, more than 3 modifiers, a held spell with no trigger, nesting deeper than 2, complexity over 12) gives `valid == false` and a `reason`; a field of the wrong type is refused too; shots over 24, speed, radius, pierce, chain jumps, lifetime, the timer interval and the cooldown floor are clamped (a shot cut is said in the description). All limits are constants in `limits.gd` (`SpellLimits`). Tags: `SpellTag.make(player, slot, depth, generation)` packs the int tag a shot carries (never 0); `begin_generation(player, slot, spell)` registers a built spell under the next of 8 generations of the slot and returns its tag, `profile(tag)` finds the spell a shot was born with, and `shot_started` and `shot_ended` count live shots per generation (all three depths together; a shot starts its children before it ends itself), so an old generation is freed whole with its last shot of any depth. If all 8 generations are live, the oldest's tags are listed in `revoked_tags`. **Casting:** `install(player, slot, spell)` is `begin_generation` plus removing the revoked shots from `Projectiles` (the one the player and flow call); `cast(player, slot, origin, direction, mana)` returns the mana spent or `Spells.REFUSED` (nothing built, cooling down, too little mana, no direction, every shot born in a wall) and changes nothing when refused; cooldowns are per player and slot (`cooldown_left`), ticked by `step(delta)` which the autoload runs every physics step after the projectile manager. The form picks the shots: a fan (a ring for 360 degrees) of straight shots, a ring of orbit shots round the player's anchor (refused without one), still shots, or beams. **Triggers:** a held spell is fired by its shot's hit (at the hit point), expiry (where it ended, 2 px back from a wall) or a timer (from the shot's place, every `trigger_interval`, at most 4 times), along the shot's velocity (outward from the caster for an orbit or still shot, along the beam for a ray), and cannot hit the target that fired it for 0.1 s (a beam never hits it). Each shot fires at most `trigger_max_fires` times and one player's triggers fire at most 32 held spells per step; the rest are dropped (`fires_dropped`), never queued. A chain shot jumps to the nearest other target within 96 px (never the one just hit or the one before as the chosen target; a chained beam skips only the one just hit, so it may stop at the one before if that stands in its way) with one jump fewer; a beam chains with another beam that pierces nothing; one player makes at most 16 jumps per step, the rest are dropped (`chains_dropped`). A timer shot is listed once even when a chain child takes its slot. Held spells send no `spell_cast`. `hit_profile(tag)` gives `gameplay/combat` a shared `HitProfile` (damage, knockback, element, status) or null; it is allocation-free. `bind(projectiles, events)` connects the runtime (the autoload binds itself in `_ready`; tests bind their own). Only `core/base/`, `core/spells/` and `content/spells/` read spell fields.
  - `projectiles/`: the projectile manager, one autoload, `Projectiles` (`projectiles/projectile_manager.gd`). Projectiles are rows in packed arrays, not nodes: `spawn(player, position, velocity, lifetime, radius, hit_layers, pierce, tag)` starts one, and the manager moves them all in `_physics_process` and draws them all in one `MultiMeshInstance2D`. Things that can be hit are Node2Ds registered with `add_target(node, radius, layer, owner)` (`LAYER_ENEMY`, `LAYER_PLAYER`; a target's `owner` player is never hit by that player's shots); the flag `friendly_fire` (default off, set by `coop`) makes player shots also hit `LAYER_PLAYER` targets; a spatial grid of the targets keeps hit tests cheap, and the path of each step is checked as a segment and the search widens with the largest target radius, so neither fast shots nor big targets are missed; a piercing shot hits each overlapping target once (it remembers the last 3, so an orbit ring over a bigger crowd hits some again). A hit sends `projectile_hit(player, target, position, tag)` (`tag` is the int given to `spawn`, for looking up damage) and ends the projectile unless it has `pierce` left (a piercing shot hits up to 3 targets per step); damage is `combat`'s job. A shot that ends without a hit (its life runs out, or a wall) sends `projectile_expired(player, position, tag)` once (not for a hit, leaving the bounds or a cap drop). `spawn` takes a last `motion` argument, `MOTION_STRAIGHT` or `MOTION_STILL` (the rune: it never moves and waits for a target to enter it). `spawn_orbit(player, orbit_radius, angle, angular_speed, lifetime, ...)` starts a shot that circles `player`'s anchor, which its owner sets every physics step with `set_anchor(player, position)` (`clear_anchor` ends that player's orbit shots quietly; orbit shots ignore walls). `set_homing(slot, turn_rate)` makes a straight shot turn toward the nearest target within 160 px (never a wizard), searching on the grid every 4th step and paying for it from the step's hit-work budget; `homing_aim(player, origin, direction, max_angle, layers)` does the same for a beam. `remove_by_tag(tag)` quietly removes every shot with a tag; `exclude(slot, node, seconds)` keeps one shot from hitting one target for a while; the manager's own signal `shot_ended(tag)` is sent once for every tagged shot that ends (hit, life, wall, bounds, cap drop, `clear`; after the shot's event handlers, so they can spawn children first; not for `remove_by_tag`); `event_slot` is the slot of the shot whose `projectile_hit` or `projectile_expired` is being sent (-1 otherwise and for beams), read with `get_seq_of`, `get_tag_of`, `get_velocity_of`; `get_anchor(player)` reads what the manager knows. `ray(player, origin, direction, length, pierce, layers, tag, width, exclude)` is the beam (length cut to 360 px; not charged to the hit-work budget, the spell runtime's fire cap bounds nested rays): no row, it stops at a wall, sends `projectile_impact` and `projectile_hit` for the nearest `pierce + 1` targets and returns how far it got (a handler may fire another ray, up to 4 deep). `nearest_target(point, radius, layers, exclude, exclude_also)` (it leaves the target's hit circle centre in `nearest_point`) and `targets_in(point, radius, layers, out)` search the target grid for targets whose hit circle overlaps a circle (chain, homing and area effects use them; nothing is allocated if `out` is reused). Just before each `projectile_hit`, and whenever a shot ends on a wall or pillar (target `null`), it sends `projectile_impact(player, target, position, direction)` for looks only: where the shot stopped and the unit vector it flew (`gameplay/feel` turns it into a spray or stone chips). Walls: `set_walls(rects)`, `add_wall_body(body)` (rectangle shapes of a static body; `flow` calls it for the room) and `clear_walls()` fill a grid of 8 px cells (`set_bounds` clears it); a shot whose path enters a solid cell ends there, piercing ones too (no bouncing), counted in `wall_hits` (a fast shot still hits a target in front of the wall; a walk is capped at 64 cells; `spawn` refuses a shot born inside a wall without taking a slot), and `clip_to_walls(from, to)` shortens a segment to the first wall (the wizard clips its staff tip with it). The global cap (`DEFAULT_CAP_WEB` 1,000 or `DEFAULT_CAP_DESKTOP` 3,000 by platform; `set_cap` changes it) never refuses a new shot: it drops the oldest projectile of whoever owns the most, and `dropped` counts these. Enemy shots (owner `NO_PLAYER`) are drawn in a second batch, one layer above, with their own `hostile_texture` (a spiky orb; set by `Feel`; unset, they use `texture`) and no tint, so they never read as a player's spell. Nothing allocates per frame. Tests step it by hand with `step(delta)`.
  - `pools/`: object pools; no per-frame allocations. `pools/pool.gd` is a fixed-size pool typed by its factory Callable: it makes every object up front, `acquire()` returns an object or `null` when all are out (it never grows), `release()` takes one back (a double or foreign release is refused), and optional `on_acquire` and `on_release` hooks reset state. `clear()` frees every object, including ones still handed out, so drop your references first. Pools are for nodes and effects (enemies, damage numbers); projectiles are packed-array rows and do not use them. Use `preload("res://core/pools/pool.gd")`.
- Most services arrive in M1 (docs/ROADMAP.md). Folders without code yet only hold a `.gitkeep`; so far `base/`, `events/`, `input/`, `pools/`, `projectiles/`, `registry/`, `spells/` and `ui_focus/` have code. Each service gets its entry script and a section here when it is built.
- Services that act per player take a player index 0–3. Nothing assumes a single player.

## Allowed files

Claude only. Typed GDScript, no banned APIs, file access only in `user://`. Tests for `core/` go in `tests/core/`; the runner and naming are documented in `tests/README.md`, which a later task writes.

## Rating questions

Not applicable to outside PRs, which are closed. For Claude's own changes: is it needed by more than one area, does it keep the dependency direction, and does it stay inside the performance budgets?
