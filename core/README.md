# Core

## Purpose

The shared services every other area stands on: the event bus, the content registry, input, per-player UI focus, saving, base classes, the projectile manager and object pools. Gameplay, HUD and content build on it; it builds on nothing of theirs.

## Contract

- **Dependency direction:** `core` ← `gameplay` ← `content`. `core/` depends on none of `gameplay/`, `hud/` or `content/`. It finds content by folder through `core/registry`.
- **Sub-folders, one per service:**
  - `events/`: the event bus (`spell_cast`, `enemy_died`, `player_downed`, `room_cleared`, ...). One autoload, `Events` (`events/events.gd`), with a typed signal per event and the player index first. Areas talk only through it. It owns the event definitions; each area's README lists only which events the area sends and listens to.
  - `registry/`: discovers content by folder, so no central list is edited. One autoload, `Registry` (`registry/registry.gd`), scans `content/` and `audio/` when the game starts (`scan()` again with other roots, for tests). `get_resource(folder, id)`, `get_ids(folder)`, `get_all(folder)` and `get_folders()` answer by folder (`spells`, `enemies`, `rooms`, ... the direct children of `content/`) and id; every `.tres` below a folder that has an `id` is registered, at any depth, and the first file in sorted path order wins a duplicate id (with a warning). The `demo` flag: with `demo_only` on (set from the `demo` feature tag) resources whose `demo` is false are hidden from every question. `validate_spells()` runs the spell validator on everything under `spells` and the reaction table (and in a debug build the registry pushes a warning per problem at start). `get_sound(id)` returns the `.ogg` under `audio/` whose file name is the id, or `null` when there is none; gameplay and feel ask for a sound by id and play nothing on `null`, so a missing sound is silent and never an error. It is the only script that loads from a computed path; everyone else uses literal `load("res://...")` or `preload(...)`.
  - `input/`: one autoload, `PlayerInput` (`input/input_manager.gd`); devices join with a button press and each player gets their own device. A gamepad takes the lowest free index; the keyboard and mouse only take P1 (index 0), so P2–P4 are gamepads. The `leave` action or an unplugged gamepad frees the slot. Bots add a virtual device per index (`add_virtual_device`, `send_virtual`) that goes through the same `handle_event` path as real input. Gameplay asks by player index (`get_move`, `is_action_pressed`, `is_action_just_pressed`) and never reads `Input` itself (call `is_action_just_pressed` only from `_process` or `_physics_process`). Each physical input is tracked on its own and an action takes the strongest, so releasing one of two held inputs does not cancel the other. The actions (`move_left`, `move_right`, `move_up`, `move_down`; the four staffs `staff_1` to `staff_4` on RB, RT, LB, LT, or Space, the left and right mouse buttons and Q; the menus' `accept` (A), `back` (B, which opens the builder in play) and `alternate` (X); `pause` (Start or Escape); `page_prev` and `page_next` (LB, RB); `extra` (Y; R), a menu's third action; `kind_prev` and `kind_next` (the d-pad's left and right only; Page Up, Page Down); `join`, `leave`) are in `project.godot`; the triggers are axes, so the manager routes them itself. Aim: `get_aim(player)` is the right stick as a unit vector (zero in the dead zone; `send_virtual_aim` for bots) and `is_mouse_aiming(player)` is a flag for the keyboard player (a mouse move or click sets it, the keyboard `staff_2` key, J, clears it); the wizard turns the mouse into a direction because that needs the world. `PlayerInput` sends `device_joined` and `device_left`; `coop` turns them into `player_joined` and `player_left`. `set_captured(player, true)` hides a player's move and the four staff actions from those gameplay questions (the menu actions stay) while their UI panel is open, so gameplay needs no check of its own; `get_press_count` counts presses and is never captured, so UI code loses no quick tap. A menu that steers with the sticks (the radial builder) reads `menu_move(player)` (the left stick alone on a pad, the move keys or virtual move actions otherwise) and `menu_aim(player)` (the right stick), which answer while captured. `rumble(player, weak, strong, seconds)` shakes a player's pad (never the keyboard) through `vibrator`, which tests replace. **Glyphs:** `glyph_kind(player)` says what a player holds (`input_glyphs.gd`, `Kind`: keyboard, keyboard with the mouse aiming, Xbox, PlayStation, Switch or a plain gamepad, told apart by `Input.get_joy_name` when the device joins, by brand word or by the vendor id a browser puts in the name) and `glyph_kind_changed(player)` fires when it changes (a join, a leave, the mouse aim turning on or off). `InputGlyphs.glyph(kind, action)` gives the button to draw for an action (shape, label, colour); the HUD draws it (`hud/widgets/action_glyph.gd`). A player's device only changes by leave and join, so that is when pad type changes. A keyboard joined only by a mouse click on Play holds P1 provisionally: the first gamepad to press join takes P1 over until the keyboard is used (owner 2026-10-27).
  - `ui_focus/`: per-player UI focus, because Godot has one global focus. One autoload, `UIFocus` (`ui_focus/ui_focus.gd`). `open(player, controls)` gives a player a panel; only that player's input (through `PlayerInput`) moves it: up/left and down/right step through the controls, `accept` (A) activates, `back` (B) cancels, `alternate` (X) sends `alternate` for the focused control and `page_prev` / `page_next` (LB, RB) send `paged` (presses come from `get_press_count`, so a quick tap is not lost). A panel laid out in two dimensions gives `set_navigator(player, callable)`: each move asks it for the control in that direction first (kept when the panel is opened again with new controls, cleared when it closes); `focus(player, control)` jumps to a control. An open panel captures its owner's gameplay input through `PlayerInput.set_captured`, so their wizard does not walk or cast meanwhile; opening needs a joined device. A focused control that gets disabled, hidden or freed loses focus and is never activated. It has its own signals (`opened`, `closed`, `focus_changed`, `activated`, `cancelled`, `alternate`, `paged`, player index first); a widget checks that the player is its owner. It never calls `grab_focus`, never pauses, and closes a panel when its player's device leaves. Every widget builds on it.
  - `display/`: the game window, one autoload, `Display` (`display/display.gd`; owner 2026-10-27). The `fullscreen` action (F11, Alt+Enter) and `toggle_fullscreen()` switch fullscreen on and off anywhere; `is_fullscreen()` reads the window itself. The main menu and the pause menu's Settings page have a switch. On the web the browser allows it only after a key press or click, not a gamepad button.
  - `save/`: reading and writing under `user://` only.
  - `base/`: base classes (`enemy_base.gd`, `room_base.gd`: small M1 resources with `id` and `demo`) and build info. M2's spell components (part 1) are `spell_component.gd` (`SpellComponent`: `id`, `demo`, `display_name`, `complexity` 1–4, `icon`, `kind()`, `ranges()` and `range_problems()`) and its four kinds `form_base.gd` (`FormBase`), `element_base.gd` (`ElementBase`), `modifier_base.gd` (`ModifierBase`) and `trigger_base.gd` (`TriggerBase`), each documenting its fields and allowed ranges; the element reactions are `reaction_table.gd` (`ReactionTable`, `find(status_id, element_id)`) of `reaction_row.gd` rows (`content/spells/reactions.tres` holds six reactions as twelve rows, one per direction), which have no `id`, so the registry never takes them for content. M1's `SpellBase` is gone (M2 part 11): the one way to fire is `Spells.cast_staff(player, staff, origin, direction, mana)`, which returns the mana spent or `REFUSED`. Players and bots call it and read no spell field; `tests/core/test_spell_field_reads.gd` fails when a script outside `content/spells/`, `core/base/` and `core/spells/` does. **Staffs rework (A3, docs/milestones/M2-staffs.md):** a fifth card kind, `multicast_base.gd` (`MulticastBase`: `extra_draws`, `mode` TOGETHER, SCATTER or BURST, `repeats`, `repeat_interval`, `mana_cost`, `cooldown`); the new carriers' motions (`FormBase.Motion` DASH to FAMILIAR; `carries_payload()` for rain and familiar), modifier behaviours (SHIELD to RELAY, `behaviour_strength` up to 256) and trigger events (BLOCK to ALLY), each commented with the kit that runs it; and `staff_base.gd` (`StaffBase`: `id`, `display_name`, `slots`, `draw`, `cast_delay`, `recharge`, `spread`, `ranges()`, `range_problems()`), which is not a card: staffs live in `content/wizard/staffs/`. `build_info.gd` holds the build info.
  - `story/`: `story_validator.gd` (`StoryValidator`, M2 part 23) checks lore files (`check_lore`, `check_component_lore`, `format`) and returns problems like `SpellValidator`. The registry reads `content/story/lore/**.json` on every scan: `get_lore(&"component", id)` gives the text or "", `validate_story()` the problems (also a missing lore file for any spell component), `warn_story_problems()` pushes them in a debug build.
  - `spells/` (staffs A4): `Spells.compile_staff(cards, staff)` reads a staff's cards into a `CompiledStaff` (`compiled_staff.gd`: the `casts` of one cycle, every compiled spell in `nodes`, and the `wasted` cards with reasons) with `staff_compiler.gd` (`StaffCompiler`, the reading rules of docs/milestones/M2-staffs.md); each `CompiledCast` (`compiled_cast.gd`) has its `group` (`CompiledGroup`: `spells`, `scatter`, `repeats`), the slots it read, `mana`, `delay`, `recharges`, `wrapped`, `targets` (what each card attached to) and a plain `description`. A compiled spell now also has `fallback` (on the caster or on a payload's origin), `element_ids`, `behaviours` (summed strength per `ModifierBase.Behaviour`), `payload`, `own_payload`, `node` and `slot`. `Spells.staff_view(cards, staff)` gives the builder plain values (and hands `staff` back, so a builder can preview other cards in the same staff). **The staff runtime (A5):** `install_staff(player, staff, compiled)` makes a compiled staff the build of one of a player's four staffs (a new generation; editing switches its sustained carriers off) and `cast_staff(player, staff, origin, direction, mana)` fires the next cast of its cycle, returns the mana spent or `REFUSED`, and moves the cursor (`cast_index`) and the delay (`cooldown_left`; the staff's `recharge` after the last cast). Tags (`SpellTag`) are player, staff, generation and node (the compiled spell's index, up to 511) above `1 << 20`, clear of the enemy attack tags. A shot with `arc` zaps the nearest enemy in its reach on a clock (`_step_arcs`, `_zap`: a short ray with the shot's `arc_hit`, using its trigger fires, so `on hit` goes off); `return` is a modifier behaviour. A group's carriers leave along one aim; every shot is then turned up to its staff's `spread` degrees (times its modifiers' `spread_mult`) either side, at random from the cast's seeded generator; a payload fires as a group under its spells' own tags; a fallback sends `area_hit_requested(player, position, radius, tag)` (combat answers from staffs B3). A `hold` carrier lives `HOLD_LIFETIME` and reserves the cast's mana (`mana_reserved`, `reserved_mana`) until the staff is cast again (that press casts nothing and returns 0.0; the caller decides which presses may), edited, or its last shot ends (`is_holding`). The recipe path is gone (staffs A6c): staffs are the one way to build and cast. **Multicast spread (B2b):** a `scatter` group sends each carrier in a random direction from a generator seeded by player, staff and cast count (the same cast scatters the same way); a `burst` group fires `repeats` times, `repeat_interval` seconds apart (at once for 0) at the mana of one cast; `echo` fires the carrier once more after its strength in seconds at half damage (`CompiledSpell.echo_hit`; no second echo, none for `hold`); `mirror` also fires a straight, returning or beam carrier backwards. **Payload and line carriers (B2c):** `rain` sends a `form_shown` cue `&"rain"` (its `length` is the seconds until it falls) and drops its payload on the aim point (`ray_length` or `RAIN_REACH` ahead, stopped at a wall) after its `lifetime`, then fires its own `on expire` trigger; `familiar` and `decoy` send `entity_spawn_requested` (INF seconds for `hold`), count each entity as a live shot of their tag until `entity_ended`, fire a familiar's payload on `familiar_cast_requested`, and fire an entity's `on expire` payload and `blast` (`area_hit_requested`) at its end point; a `hold` switch-off, a rebuild or a revoked build sends `entity_end_requested`; `wall` is `shots` still shots across the aim, `spread` pixels apart, `WALL_REACH` ahead (shield charges apply); `fissure` is a beam that pierces up to `FISSURE_PIERCE` targets. **Moves, areas and refunds (B2d):** `teleport` asks for a blink along the aim (`caster_move_requested`, cut at the first wall); a `hook` hit asks the caster to move to the hit, a `swap` hit moves the target to the caster (`target_move_requested`) and the caster to the target; `recoil` pushes the caster back `strength` pixels from each firing of the cast (`mirror` cancels it); `caster_move_finished` for a dash, teleport or hook is the carrier's end point (its `blast` and `on expire` payload); a spent, expired or beam-ending shot with `blast` sends `area_hit_requested`; `siphon` sends `mana_refund_requested` per hit. The later firings wait in a queue of at most `SpellLimits.MAX_PENDING` (`delayed_dropped` counts the overflow), start from where the caster has moved to, and are dropped when the staff is rebuilt or switched off.
  - `spells/`: `validator.gd` (`SpellValidator`, M2 part 9) checks cards, staffs and the reaction table and returns problems as rule, file, field and fix (`check_all`, `check_component`, `check_staff`, `check_reactions`, `format`); the registry runs it, `tests/content/spells/test_validators.gd` fails on any problem. The spell runtime is one autoload, `Spells` (`spells/spells.gd`), on staffs since the staffs rework: see the staffs paragraphs above and below for compiling (`compile_staff`, `StaffCompiler`), the builder view (`staff_view`), installing (`install_staff`, `begin_generation`) and casting (`cast_staff`). Payloads are fired by their shot's hit (at the hit point), expiry (where it ended, 2 px back from a wall) or a timer (from the shot's place, every `trigger_interval`), along the shot's velocity (outward from the caster for an orbit or still shot, along the beam for a ray), and cannot hit the target that fired them for 0.1 s (a beam never hits it). Each shot fires at most `trigger_max_fires` times and one player's triggers fire at most 32 payloads per step (an engine safeguard); the rest are dropped (`fires_dropped`), never queued. A chain shot jumps to the nearest other target within 96 px (never the one just hit or the one before) with one jump fewer; a beam chains with another beam; one player makes at most 16 jumps per step (`chains_dropped`). Payloads send no `spell_cast`. `component_name(id)`, `component_icon(id)`, `component_kind(id)`, `component_description(id)` and `component_stats(id)` (up to three short lines of the card's own numbers: "Dmg 3x8", "Mana x1.5", "Burn 3s") give the HUD what it shows of a card without reading its fields. `hit_profile(tag)` gives `gameplay/combat` a shared `HitProfile` (damage, knockback, elements, status) or null; it is allocation-free. `bind(projectiles, events)` connects the runtime (the autoload binds itself in `_ready`; tests bind their own). The numbers left are engine safeguards and tuning in `limits.gd` (`SpellLimits`); there are no build limits. Only `core/base/`, `core/spells/` and `content/spells/` read card fields.
  - `projectiles/`: the projectile manager, one autoload, `Projectiles` (`projectiles/projectile_manager.gd`). Projectiles are rows in packed arrays, not nodes: `spawn(player, position, velocity, lifetime, radius, hit_layers, pierce, tag)` starts one, and the manager moves them all in `_physics_process` and draws them all in one `MultiMeshInstance2D`. Things that can be hit are Node2Ds registered with `add_target(node, radius, layer, owner)` (`LAYER_ENEMY`, `LAYER_PLAYER`; a target's `owner` player is never hit by that player's shots); the flag `friendly_fire` (default off, set by `coop`) makes player shots also hit `LAYER_PLAYER` targets; a spatial grid of the targets keeps hit tests cheap, and the path of each step is checked as a segment and the search widens with the largest target radius, so neither fast shots nor big targets are missed; a piercing shot hits each overlapping target once (it remembers the last 3, so an orbit ring over a bigger crowd hits some again). A hit sends `projectile_hit(player, target, position, tag)` (`tag` is the int given to `spawn`, for looking up damage) and ends the projectile unless it has `pierce` left (a piercing shot hits up to 3 targets per step); damage is `combat`'s job. A shot that ends without a hit (its life runs out, or a wall) sends `projectile_expired(player, position, tag)` once (not for a hit, leaving the bounds or a cap drop). `spawn` takes a last `motion` argument, `MOTION_STRAIGHT` or `MOTION_STILL` (the rune: it never moves and waits for a target to enter it). `spawn_orbit(player, orbit_radius, angle, angular_speed, lifetime, ...)` starts a shot that circles `player`'s anchor, which its owner sets every physics step with `set_anchor(player, position)` (`clear_anchor` ends that player's orbit shots quietly; orbit shots ignore walls). `set_homing(slot, turn_rate, within)` makes a straight shot turn toward a target no further than `within` px (never a wizard), searching on the grid every 4th step and paying for it from the step's hit-work budget. The target is picked at random among those in reach (seeded, so a replay picks the same) and kept while it stays in reach, alive and not just hit, so a fan of homing shots spreads over a group. `homing_point(player, origin, direction, max_angle, layers, within, keep, pick_seed)` is the same pick for anything else (a cone of `max_angle`, PI for any way; `homing_target` is the id to pass back as `keep`): `homing_aim` bends a beam's or teleport's way with it, `home_velocity` turns a moving thing at a turn rate (a dash, whether it moves a shot through `move_shot(slot, offset, seconds, turn_rate, within)` or the wizard), and `turned_toward` is the one turn they all share. Outside the manager, a homing thing holds a `Homing` (`spells/homing.gd`: its spell's turn, reach and bend, the target it keeps and its seed) and calls `steer`, `point` or `aim`; a beam's legs, a teleport and the wizard's dash (`Spells.move_homing`, read by the player) do. There is no default range: the spell runtime passes `CompiledSpell.homing_range`, set by `StaffCompiler.homing_range` from the Homing card's `behaviour_reach` (a beam or teleport at least as far as it goes; 0 where homing cannot steer, and the card is wasted). `remove_by_tag(tag)` quietly removes every shot with a tag; `exclude(slot, node, seconds)` keeps one shot from hitting one target for a while; the manager's own signal `shot_ended(tag)` is sent once for every tagged shot that ends (hit, life, wall, bounds, cap drop, `clear`; after the shot's event handlers, so they can spawn children first; not for `remove_by_tag`); `event_slot` is the slot of the shot whose `projectile_hit` or `projectile_expired` is being sent (-1 otherwise and for beams), read with `get_seq_of`, `get_tag_of`, `get_velocity_of`; `get_anchor(player)` reads what the manager knows. `ray(player, origin, direction, length, pierce, layers, tag, width, exclude)` is the beam (length cut to 360 px; not charged to the hit-work budget, the spell runtime's fire cap bounds nested rays): no row, it stops at a wall, sends `projectile_impact` and `projectile_hit` for the nearest `pierce + 1` targets and returns how far it got (a handler may fire another ray, up to 4 deep); `ray_curve(player, origin, bend, end, ...)` is the same along a bent beam (8 pieces), and with `hit` false only finds how far it gets; both leave `ray_end` and `ray_end_heading`. Each shot has a caster (`set_caster_shot`, `set_caster_point`, `get_caster_of`, `caster_shot_of`, `is_cast_by_wizard`): its player's anchor by default, which an orbit circles and a returning shot comes back to; `move_shot(slot, offset, seconds)` moves a shot on top of its own motion (a payload's dash, hook or recoil). `nearest_target(point, radius, layers, exclude, exclude_also)` (it leaves the target's hit circle centre in `nearest_point`) and `targets_in(point, radius, layers, out)` search the target grid for targets whose hit circle overlaps a circle (chain, homing and area effects use them; nothing is allocated if `out` is reused). Just before each `projectile_hit`, and whenever a shot ends on a wall or pillar (target `null`), it sends `projectile_impact(player, target, position, direction)` for looks only: where the shot stopped and the unit vector it flew (`gameplay/feel` turns it into a spray or stone chips). Walls: `set_walls(rects)`, `add_wall_body(body)` (rectangle shapes of a static body; `flow` calls it for the room) and `clear_walls()` fill a grid of 8 px cells (`set_bounds` clears it); a shot whose path enters a solid cell ends there, piercing ones too (unless it has bounces left or is a ghost), counted in `wall_hits` (a fast shot still hits a target in front of the wall; a walk is capped at 64 cells; `spawn` refuses a shot born inside a wall without taking a slot), and `clip_to_walls(from, to)` shortens a segment to the first wall (the wizard clips its staff tip with it), and `circle_blocked(center, radius)` says whether a circle is out of the bounds or touches a wall (a teleport checks the body with it). The global cap (`DEFAULT_CAP_WEB` 500 or `DEFAULT_CAP_DESKTOP` 3,000 by platform; `set_cap` changes it) never refuses a new shot: it drops the oldest projectile of whoever owns the most, and `dropped` counts these. Enemy shots (owner `NO_PLAYER`) are drawn in a second batch, one layer above, with their own `hostile_texture` (a spiky orb; set by `Feel`; unset, they use `texture`) and no tint, so they never read as a player's spell. A player's shot is built by `shot_core.gdshader` on a pixel grid, in three batches (bolts, runes, orbit shots; staffs B6a): a small core shaped by its body kind (`KIND_BOLT`, `KIND_RUNE`, `KIND_ORBIT`) in the colour set with `set_core(slot, color)` (the spell runtime passes the first infusion's tint; white when unset; `get_core_of(slot)` reads it) and outlined in the player's shadow shade, a short trail in the player's colour behind a bolt, and particles given off from its tail in the styles of all its cards, mixed at random, set with `set_look(slot, look)` (`pack_look(kinds)` packs `LOOK_*` kinds as a set of bits; the runtime passes `CompiledSpell.look`), drawn `look_size(radius)` pixels across (one-pixel lines at every zoom); so a shot shows who fired it and which cards it carries. `tint_of(player)` is the tint Feel uses for the beams and rings it draws. **The projectile kit (staffs B1):** `set_bounce(slot, times)`, `set_ghost`, `set_spiral(slot, width)`, `set_return`, `set_linger(slot, seconds)`, `set_growth(slot, factor)` (`get_growth_of`), `set_sticky(slot, seconds)`, `set_shield(slot, charges)` (`shot_blocked`; `get_shield_of`), `set_self_hit` (a shot may hit its caster once it has left the caster's hitbox; `is_self_live`) and `set_ally_hit` (hits teammates' wizards) give a flying shot its behaviours; the spell runtime sets them from the compiled `BOUNCE`, `GHOST`, `SPIRAL`, `LINGER`, `GROWTH`, `STICKY` and `SHIELD` modifier strengths and the `RETURN` carrier. Without ally-hit or friendly fire a shot passes teammates' wizards and sends `ally_passed(player, ally, position, tag)` once for each. `expired_on_wall` is true while the `projectile_expired` of a shot that ended on a wall is sent (for `on wall`). `shot_blocked` is sent with `event_slot` set to the shielded shot, and `target_owner_of(node)` gives the player a registered target belongs to. **The trigger events (staffs B2a, `core/spells`):** `Spells` fires a carrier's payload from where the event happened for `on block` (`shot_blocked`, `shield_blocked`), `on kill` (`kill_landed`), `on wall` (`projectile_expired` while `expired_on_wall`), `on reaction` (`reaction_landed`) and `on ally` (`ally_passed`), each limited by the trigger's `max_fires` per shot (a beam counts its fires per cast; an event with no live shot behind it fires once per carrier per step); `on cast` fires at once from the caster's origin; `on hurt` fires from the wizard (`wizard_hurt`) for every live carrier of that player, up to `max_fires` each. `relay` makes a shot that passes a teammate hit with the elements and status of that player's last cast that had an infusion (`Spells.hit_profile` answers per shot while the hit is being sent). Nothing allocates per frame. Tests step it by hand with `step(delta)`.
  - `pools/`: object pools; no per-frame allocations. `pools/pool.gd` is a fixed-size pool typed by its factory Callable: it makes every object up front, `acquire()` returns an object or `null` when all are out (it never grows), `release()` takes one back (a double or foreign release is refused), and optional `on_acquire` and `on_release` hooks reset state. `clear()` frees every object, including ones still handed out, so drop your references first. Pools are for nodes and effects (enemies, damage numbers); projectiles are packed-array rows and do not use them. Use `preload("res://core/pools/pool.gd")`.
- Most services arrive in M1 (docs/ROADMAP.md). Folders without code yet only hold a `.gitkeep`; so far `base/`, `display/`, `events/`, `input/`, `pools/`, `projectiles/`, `registry/`, `spells/` and `ui_focus/` have code. Each service gets its entry script and a section here when it is built.
- Services that act per player take a player index 0–3. Nothing assumes a single player.

## Allowed files

Claude only. Typed GDScript, no banned APIs, file access only in `user://`. Tests for `core/` go in `tests/core/`; the runner and naming are documented in `tests/README.md`, which a later task writes.

## Review questions

Is it needed by more than one area, does it keep the dependency direction, and does it stay inside the performance budgets?
