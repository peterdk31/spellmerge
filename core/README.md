# Core

## Purpose

The shared services every other area stands on: the event bus, the content registry, input, per-player UI focus, saving, base classes, the projectile manager and object pools. Gameplay, HUD and content build on it; it builds on nothing of theirs.

## Contract

- **Dependency direction:** `core` ← `gameplay` ← `content`. `core/` depends on none of `gameplay/`, `hud/` or `content/`. It finds content by folder through `core/registry`.
- **Sub-folders, one per service:**
  - `events/`: the event bus (`spell_cast`, `enemy_died`, `player_downed`, `room_cleared`, ...). One autoload, `Events` (`events/events.gd`), with a typed signal per event: caster-keyed events name the actor id first (`caster`), seat-keyed ones the seat (`player`), actors G3b. Areas talk only through it. Beside it, `events/online_why.gd` (`OnlineWhy`): the names `online_changed` gives as its reason (why hosting or joining failed, who left) with each name's facts, and the keys of the online line's facts; net names, the HUD words (online-lobby L5b). **Commands** (online-ready N2): the HUD's requests the simulation hears (`InputFrame.COMMAND_NAMES`: the builder's, the pause menu's, the hub's, the items', rewards, doors) apply at the next tick's start, never mid-tick: the bus hands each to `command_sink` (the `Frames` autoload, `sim/`), which puts it into its seat's next input frame and applies it then (`apply_command`); the HUD sends them as before, and the simulation hears them through `listen(name, callable)`, never by connecting to the signal. With no sink (a test's own bus) a command applies as it is sent. A new HUD request the simulation hears goes into `InputFrame.COMMAND_NAMES` with its shape, and its listener uses `listen`. It owns the event definitions; each area's README lists only which events the area sends and listens to.
  - `registry/`: discovers content by folder, so no central list is edited. One autoload, `Registry` (`registry/registry.gd`), scans `content/` and `audio/` when the game starts (`scan()` again with other roots, for tests). `get_resource(folder, id)`, `get_ids(folder)`, `get_all(folder)` and `get_folders()` answer by folder (`spells`, `enemies`, `rooms`, ... the direct children of `content/`) and id (`add(folder, resource)` and `remove(folder, id)` put a test's fixture in and take it out again); every `.tres` below a folder that has an `id` is registered, at any depth, and the first file in sorted path order wins a duplicate id (with a warning). Every build sees every resource: there is no demo subset (owner, 2026-11-05). `validate_spells()` runs the spell validator on everything under `spells` and the reaction table (and in a debug build the registry pushes a warning per problem at start). `get_sound(id)` returns the sound whose file name is the id, or `null` when there is none: an `.ogg` or a `.tres` (an `AudioStreamRandomizer` of baked variants, docs/milestones/sound.md, section 3) under `audio/` or under a content item's `sounds/` folder, never a file under a `variants/` folder; the content scan skips `sounds/` folders, so a sound loads when first asked for; `sound_ids()` lists every id with a file (the sound room's, tests/sound_room); one id in two files is a warning and a line of `sound_clashes()`, which a test fails on for the game's; gameplay and feel ask for a sound by id and play nothing on `null`, so a missing sound is silent and never an error. **For the editor**, where the autoload does not run, `Registry.scan_folder(folder)` (static, through the script: `preload("res://core/registry/registry.gd")`) reads one folder there and then, in id order, as `scan()` reads it (ground cover GC2: the editor's cover preview finds the cover kinds, `cover`, by it). It is the only script that loads from a computed path; everyone else uses literal `load("res://...")` or `preload(...)`.
  - `input/`: one autoload, `PlayerInput` (`input/input_manager.gd`); devices join with a button press and each player gets their own device. A gamepad takes the lowest free index; the keyboard and mouse only take P1 (index 0), so P2–P4 are gamepads. The pause menu's "Leave game" (`seat_leave_requested`, which the manager hears; items I2: it replaced the `leave` action) frees the slot. **An unplugged gamepad keeps its seat** (owner, 2026-11-13): the seat waits for it (`is_waiting`), holding nothing, and the manager asks the game to stop meanwhile (the command `pad_wait_requested(player, 1)`, heard by co-op; asked again in every room entered while it waits). The seat plays again when that gamepad connects again (the same device id) or presses something (a release or a stick at rest does not count), or when another gamepad not seated presses `join` (it takes the lowest waiting seat before any free slot), or the keyboard's `join` when this machine's first seat waits; then `pad_wait_requested(player, 0)`. The keyboard and virtual devices never wait. Bots join with a virtual device per index (`add_virtual_device`; `send_virtual` for a menu's buttons, through the same `handle_event` path as real input) and fill their seat's input frames (`sim/`, `Frames.set_source`). **The simulation never reads a device** (online-ready N2): `local_input.gd` (`LocalInput`) is the local input layer in front of a seat's input frame (the walk, the stick's aim hold, the mouse turned into a direction from the hand, the staff buttons' press counts, captured), kept per seat by the `Frames` autoload. Menus, the HUD and UI focus ask by player index (`get_move`, `is_action_pressed`, `is_action_just_pressed`) and never reads `Input` itself (call `is_action_just_pressed` only from `_process` or `_physics_process`). Each physical input is tracked on its own and an action takes the strongest, so releasing one of two held inputs does not cancel the other. The actions (`move_left`, `move_right`, `move_up`, `move_down`; the four staffs `staff_1` to `staff_4` on RB, RT, LB, LT, or Space, the left and right mouse buttons and Q; the menus' `accept` (A), `back` (B; E, which opens the builder in play) and `alternate` (X); `pause` (Start or Escape); `page_prev` and `page_next` (LB, RB); `extra` (Y; R), a menu's third action; `kind_prev` and `kind_next` (the d-pad's left and right only; Page Up, Page Down); **the d-pad never walks** (the owner, 2026-11-20: `move_*` are the left stick, WASD and the arrows only); its arms are `quick_up`, `quick_right`, `quick_down` and `quick_left` (`QUICK_ACTIONS`, by quick-use slot, with `QUICK_WAYS`; on the keyboard 1, 2, 3 and 4, which nothing else takes): in play each uses what its slot is bound to, on the held Y map they move the teleport pick, and in a menu they step the focus as the stick does (`ui_focus/`); `InputGlyphs.DPAD` draws the whole d-pad ("1-4" on the keyboard); `take` (A; F or Enter, never Space: the item in reach in play, items I6); `inventory` (Select; Tab: the inventory, items I7); `join`) are in `project.godot`; the triggers are axes, so the manager routes them itself. Aim: `get_aim(player)` is the right stick as a unit vector (zero in the dead zone; `send_virtual_aim` for bots) and `is_mouse_aiming(player)` is a flag for the keyboard player (a mouse move or click sets it, the keyboard `staff_2` key, J, clears it); the local input layer (`LocalInput`) turns the mouse into a direction from the hand of the actor the seat drives, because that needs the world. `PlayerInput` sends `device_joined` and `device_left`; the frames service (`sim/`) turns them into the simulation's `seat_joined` and `seat_left`, and `coop` those into `player_joined` and `player_left`. `set_captured(player, true)` hides a player's move and the four staff actions from those gameplay questions (the menu actions stay) while their UI panel is open, so gameplay needs no check of its own; `get_press_count` counts presses and is never captured, so UI code loses no quick tap. A menu that steers with the sticks (the radial builder) reads `menu_move(player)` (the left stick alone on a pad, the move keys or virtual move actions otherwise) and `menu_aim(player)` (the right stick), which answer while captured; `menu_tilt(player)` is the right stick with how far it is pushed (0 to 1 past the dead zone), for the radial's zoom and kind rings. `is_held(player, action)` says whether a button is down captured or not, for the menu that holds the capture (the radial's LT held clears). `rumble(player, weak, strong, seconds)` shakes a player's pad (never the keyboard) through `vibrator`, which tests replace. **Glyphs:** `glyph_kind(player)` says what a player holds (`input_glyphs.gd`, `Kind`: keyboard, keyboard with the mouse aiming, Xbox, PlayStation, Switch or a plain gamepad, told apart by `Input.get_joy_name` when the device joins, by brand word or by the vendor id a browser puts in the name) and `glyph_kind_changed(player)` fires when it changes (a join, a leave, the mouse aim turning on or off). `InputGlyphs.glyph(kind, action)` gives the button to draw for an action (shape, label, colour); the HUD draws it (`hud/widgets/action_glyph.gd`). A player's device only changes by leave and join, so that is when pad type changes. A keyboard joined only by a mouse click on Play holds P1 provisionally: the first gamepad to press join takes P1 over until the keyboard is used (owner 2026-10-27). **This machine's seats** (`set_own_seats(first, count)`; all four from P1 unless told; netcode spike S4): the slots its real devices may take. The keyboard takes the first of them, a gamepad the lowest free one; a device already on one of them keeps it (its wizard is not touched) and the others join again or stay out (`reseat`: everyone anew, a menu's reset); virtual devices are not touched; a machine that plays a run with another one is told its one seat, and the input layer knows nothing of why. **Seats another machine gives** (online lobby L2): while `join_asker` is set (net/ sets it on a machine that plays another machine's run), a device that would join is not seated here; the asker is called with the device and seats it later where it says, with `join_as(device, seat)`. The layer knows nothing of why.
  - `actors/`: the actor table, one autoload, `Actors` (`actors/actors.gd`; actors G2, docs/milestones/M2-actors.md). An actor is anything that acts (a player, an enemy), and its id (0–1023, `ACTORS`) is its row in every system. `open(team, ramp, seat)` hands out the lowest free id (`NONE`, -1, when full), `close(id)` frees it; `is_open`, `team_of` (`TEAM_WIZARDS`, `TEAM_ENEMIES`: for aim only), `ramp_of` (0–3 the hat colours, `RAMP_ENEMY`), `seat_of` (0–3 or `NONE`); `set_driver(id, team, seat)` is a controller change, and a seat drives one actor at a time (the newer takes it, the older is left unseated); `actor_of_seat(seat)`; `set_home(id, seat)` and `home_of_seat(seat)` (a seat's own body, kept while it drives another actor); `shown_of_seat(seat)` (the body a seat's HUD is about: the one it drives, else its own; items I8); `budget_of(id)` is the seat while a seat drives it, else `SHARED` (4); `set_node`/`node_of` keep only an instance id (null once freed); `clear()`. Bad ids answer `NONE` and change nothing. Packed arrays, nothing allocated after start. The bodies open their own ids (players, enemies that cast, the actor kit), and every system keys its arrays by them (G3). See `actors/README.md`.
  - `items/`: what an item is (items I3, docs/milestones/items.md): the kinds table (`ItemKinds.RULES`: each kind's bag, whether it stacks, its content folders, what can be done with one held) and the stack (`ItemStack`: a kind, an id, a count; a staff's number, staff, cards and kept mana). A simulation folder. Who holds stacks is the actor kit's `Inventory`. See `items/README.md`.
  - `sim/`: the simulation's own tools and its one input path (online-ready, phase N). **Input (N2):** `InputFrame` (one seat's input for one tick: the move and aim quantised, the staff buttons, captured, the tick's commands; strict bytes), the `Frames` autoload (`frames.gd`: at each tick's start (the Tick calls `tick` first, `sim/tick.gd`), each seat's frame from a replay, a `FrameSource` such as a bot, or its device through `LocalInput`; the commands applied; `record` and `play`), `Replay` (a run's start, seed, content and frames; `user://replays/` only). A `PlayerController` builds its intent from `Frames.frame_of(seat)`. **The state:** `StateWalk` (every member of a simulation script is state unless listed in `DERIVED` or `VIEW`; references to other bodies in `REFS` are state, walked as who they point at), `SimHash` (a hash per area), `Desync` (the first tick two runs part, and the members that differ) and `SimSeed` (`SimSeed.fresh()`: the one seed nobody chose; simulation code calls no `randomize()`, global dice or clock, a test reads their source). Tests and tools only, never a normal tick, except `SimSeed`. Its README lists the simulation folders.
  - `ui_focus/`: per-player UI focus, because Godot has one global focus. One autoload, `UIFocus` (`ui_focus/ui_focus.gd`). `open(player, controls)` gives a player a panel; only that player's input (through `PlayerInput`) moves it: up/left and down/right step through the controls, `accept` (A) activates, `back` (B) cancels, `alternate` (X) sends `alternate` for the focused control and `page_prev` / `page_next` (LB, RB) send `paged` (presses come from `get_press_count`, so a quick tap is not lost). A panel laid out in two dimensions gives `set_navigator(player, callable)`: each move asks it for the control in that direction first (kept when the panel is opened again with new controls, cleared when it closes); `focus(player, control)` jumps to a control. An open panel captures its owner's gameplay input through `PlayerInput.set_captured`, so their staff does not walk or cast meanwhile; opening needs a joined device. A focused control that gets disabled, hidden or freed loses focus and is never activated. It has its own signals (`opened`, `closed`, `focus_changed`, `activated`, `cancelled`, `alternate`, `paged`, player index first); a widget checks that the player is its owner. It never calls `grab_focus`, never pauses, and closes a panel when its player's device leaves. Every widget builds on it.
  - `settings/`: the numbers of player settings that more than one area reads, so neither reads the other: `SplitScreenSetting` (`settings/split_screen_setting.gd`; the owner, 2026-11-19), the pause menu's "Split screen" modes (`DYNAMIC`, the Voronoi split, the default; the menu sends `mote_density_changed`, which Feel applies with `set_mote_density`; `FloorMarks` (`settings/floor_marks.gd`; spell spectacle P2a), the "Floor marks" switch's platform default (`default_on()`, on for both until P2 measures the web); the menu sends `floor_marks_changed`, which Feel applies with `set_floor_marks`; `TaillessMotes` (`settings/tailless_motes.gd`; S5 step 4, a dev setting), the stops of the "Tailless motes" slider (2048, 4096, 8192: the births' pool with the tails off) and `frame_rows_of`, the motes' rows a frame for a pool; the menu sends `tailless_motes_changed`, which the projectile manager applies with `set_tailless_pool` and feel with `Motes.frame_rows`; the atmosphere's (docs/milestones/atmosphere.md, "Settings"): `ShadowsSetting`, `FogSetting`, `AmbientParticles` and `EnvironmentInteraction` (`settings/shadows_setting.gd`, `fog_setting.gd`, `ambient_particles.gd`, `environment_interaction.gd`), the platform defaults of the "Shadows", "Fog", "Ambient particles" and "Environment interaction" switches (sent as `shadows_changed`, `fog_changed`, `ambient_particles_changed`, `environment_interaction_changed`, which Feel applies), `SpellLightSetting` the "Dynamic lighting" switch's (once "Spell light"), and `AmbienceVolume` (`settings/ambience_volume.gd`), the "Ambience volume" slider's range in percent, `snap`, `share_of` and `word_of` (sent as `ambience_volume_changed`, which Audio applies to its `Ambience` bus), and `AudioVolumes` (`settings/audio_volumes.gd`, docs/milestones/sound.md, section 5): the saved keys of the four volume settings, Music, Sound, Ambience and UI, all on `AmbienceVolume`'s stops and curve (`share_of`), each sent as its own event (`music_volume_changed`, `sound_volume_changed`, `ambience_volume_changed`, `ui_volume_changed`) that Audio applies to its bus; machine settings, never a run's rules. Folders without code yet only hold a `.gitkeep`; so far `actors/`, `audio/`, `base/`, `native/`, `display/`, `events/`, `input/`, `pools/`, `projectiles/`, `registry/`, `spells/` and `ui_focus/` have code. Each service gets its entry script and a section here when it is built.
- Services that act per caster take an actor id (`core/actors`); only the HUD's, input's and co-op's take a seat 0–3. Nothing assumes a single player.

## Allowed files

Claude only. Typed GDScript, shaders and shader includes (`.gdshader`, `.gdshaderinc`, with their `.uid`), no banned APIs, file access only in `user://`. Tests for `core/` go in `tests/core/`; the runner and naming are documented in `tests/README.md`, which a later task writes.
