# Core

## Purpose

The shared services every other area stands on: the event bus, the content registry, input, per-player UI focus, saving, base classes, the projectile manager and object pools. Gameplay, HUD and content build on it; it builds on nothing of theirs.

## Contract

- **Dependency direction:** `core` ← `gameplay` ← `content`. `core/` depends on none of `gameplay/`, `hud/` or `content/`. It finds content by folder through `core/registry`.
- **Sub-folders, one per service:**
  - `events/`: the event bus (`spell_cast`, `enemy_died`, `player_downed`, `room_cleared`, ...). One autoload, `Events` (`events/events.gd`), with a typed signal per event: caster-keyed events name the actor id first (`caster`), seat-keyed ones the seat (`player`), actors G3b. Areas talk only through it. It owns the event definitions; each area's README lists only which events the area sends and listens to.
  - `registry/`: discovers content by folder, so no central list is edited. One autoload, `Registry` (`registry/registry.gd`), scans `content/` and `audio/` when the game starts (`scan()` again with other roots, for tests). `get_resource(folder, id)`, `get_ids(folder)`, `get_all(folder)` and `get_folders()` answer by folder (`spells`, `enemies`, `rooms`, ... the direct children of `content/`) and id; every `.tres` below a folder that has an `id` is registered, at any depth, and the first file in sorted path order wins a duplicate id (with a warning). The `demo` flag: with `demo_only` on (set from the `demo` feature tag, except in `dev` and `preview` builds, `demo_only_for`) resources whose `demo` is false are hidden from every question. `validate_spells()` runs the spell validator on everything under `spells` and the reaction table (and in a debug build the registry pushes a warning per problem at start). `get_sound(id)` returns the `.ogg` under `audio/` whose file name is the id, or `null` when there is none; gameplay and feel ask for a sound by id and play nothing on `null`, so a missing sound is silent and never an error. It is the only script that loads from a computed path; everyone else uses literal `load("res://...")` or `preload(...)`.
  - `input/`: one autoload, `PlayerInput` (`input/input_manager.gd`); devices join with a button press and each player gets their own device. A gamepad takes the lowest free index; the keyboard and mouse only take P1 (index 0), so P2–P4 are gamepads. The `leave` action or an unplugged gamepad frees the slot. Bots add a virtual device per index (`add_virtual_device`, `send_virtual`) that goes through the same `handle_event` path as real input. Gameplay asks by player index (`get_move`, `is_action_pressed`, `is_action_just_pressed`) and never reads `Input` itself (call `is_action_just_pressed` only from `_process` or `_physics_process`). Each physical input is tracked on its own and an action takes the strongest, so releasing one of two held inputs does not cancel the other. The actions (`move_left`, `move_right`, `move_up`, `move_down`; the four staffs `staff_1` to `staff_4` on RB, RT, LB, LT, or Space, the left and right mouse buttons and Q; the menus' `accept` (A), `back` (B, which opens the builder in play) and `alternate` (X); `pause` (Start or Escape); `page_prev` and `page_next` (LB, RB); `extra` (Y; R), a menu's third action; `kind_prev` and `kind_next` (the d-pad's left and right only; Page Up, Page Down); `join`, `leave`) are in `project.godot`; the triggers are axes, so the manager routes them itself. Aim: `get_aim(player)` is the right stick as a unit vector (zero in the dead zone; `send_virtual_aim` for bots) and `is_mouse_aiming(player)` is a flag for the keyboard player (a mouse move or click sets it, the keyboard `staff_2` key, J, clears it); the player turns the mouse into a direction because that needs the world. `PlayerInput` sends `device_joined` and `device_left`; `coop` turns them into `player_joined` and `player_left`. `set_captured(player, true)` hides a player's move and the four staff actions from those gameplay questions (the menu actions stay) while their UI panel is open, so gameplay needs no check of its own; `get_press_count` counts presses and is never captured, so UI code loses no quick tap. A menu that steers with the sticks (the radial builder) reads `menu_move(player)` (the left stick alone on a pad, the move keys or virtual move actions otherwise) and `menu_aim(player)` (the right stick), which answer while captured; `menu_tilt(player)` is the right stick with how far it is pushed (0 to 1 past the dead zone), for the radial's zoom and kind rings. `rumble(player, weak, strong, seconds)` shakes a player's pad (never the keyboard) through `vibrator`, which tests replace. **Glyphs:** `glyph_kind(player)` says what a player holds (`input_glyphs.gd`, `Kind`: keyboard, keyboard with the mouse aiming, Xbox, PlayStation, Switch or a plain gamepad, told apart by `Input.get_joy_name` when the device joins, by brand word or by the vendor id a browser puts in the name) and `glyph_kind_changed(player)` fires when it changes (a join, a leave, the mouse aim turning on or off). `InputGlyphs.glyph(kind, action)` gives the button to draw for an action (shape, label, colour); the HUD draws it (`hud/widgets/action_glyph.gd`). A player's device only changes by leave and join, so that is when pad type changes. A keyboard joined only by a mouse click on Play holds P1 provisionally: the first gamepad to press join takes P1 over until the keyboard is used (owner 2026-10-27).
  - `actors/`: the actor table, one autoload, `Actors` (`actors/actors.gd`; actors G2, docs/milestones/M2-actors.md). An actor is anything that acts (a player, an enemy), and its id (0–1023, `ACTORS`) is its row in every system. `open(team, ramp, seat)` hands out the lowest free id (`NONE`, -1, when full), `close(id)` frees it; `is_open`, `team_of` (`TEAM_WIZARDS`, `TEAM_ENEMIES`: for aim only), `ramp_of` (0–3 the hat colours, `RAMP_ENEMY`), `seat_of` (0–3 or `NONE`); `set_driver(id, team, seat)` is a controller change, and a seat drives one actor at a time (the newer takes it, the older is left unseated); `actor_of_seat(seat)`; `set_home(id, seat)` and `home_of_seat(seat)` (a seat's own body, kept while it drives another actor); `budget_of(id)` is the seat while a seat drives it, else `SHARED` (4); `set_node`/`node_of` keep only an instance id (null once freed); `clear()`. Bad ids answer `NONE` and change nothing. Packed arrays, nothing allocated after start. The bodies open their own ids (players, enemies that cast, the actor kit), and every system keys its arrays by them (G3). See `actors/README.md`.
  - `ui_focus/`: per-player UI focus, because Godot has one global focus. One autoload, `UIFocus` (`ui_focus/ui_focus.gd`). `open(player, controls)` gives a player a panel; only that player's input (through `PlayerInput`) moves it: up/left and down/right step through the controls, `accept` (A) activates, `back` (B) cancels, `alternate` (X) sends `alternate` for the focused control and `page_prev` / `page_next` (LB, RB) send `paged` (presses come from `get_press_count`, so a quick tap is not lost). A panel laid out in two dimensions gives `set_navigator(player, callable)`: each move asks it for the control in that direction first (kept when the panel is opened again with new controls, cleared when it closes); `focus(player, control)` jumps to a control. An open panel captures its owner's gameplay input through `PlayerInput.set_captured`, so their staff does not walk or cast meanwhile; opening needs a joined device. A focused control that gets disabled, hidden or freed loses focus and is never activated. It has its own signals (`opened`, `closed`, `focus_changed`, `activated`, `cancelled`, `alternate`, `paged`, player index first); a widget checks that the player is its owner. It never calls `grab_focus`, never pauses, and closes a panel when its player's device leaves. Every widget builds on it.
  - `settings/`: the numbers of player settings that more than one area reads, so neither reads the other: `EffectSlots` (`settings/effect_slots.gd`; owner 2026-10-27), the range, step and default of the pause menu's "Effect slots" slider and feel's effect batch, and `snap`. (`EnemyFire`, the Enemy fire switch's default, went with the switch in actors G3c.)
  - `loading/`: the loading screen's service, one autoload, `Loading` (`loading/loading.gd`, last in the autoload list; owner 2026-10-29: the work before playing happens behind a loading screen, not on the menu or in the room). `run(tasks, done)` does a list of LoadTasks one unit a frame (after `WAIT_FRAMES`, so the screen is drawn first), sends `loading_started`, `loading_progressed(done, total)` and `loading_finished` (the HUD's screen, `hud/panels/loading/`, is drawn from those alone), then calls `done`; `cancel()` drops it without `done`; one load at a time (`is_loading`, `progress`). A LoadTask (`loading/load_task.gd`) is a RefCounted with `units`, `units_done`, `begin(host)`, `step` (one unit), `is_done`, `end`; the shader warm-up is one (`projectiles/shader_warmup.gd`). **Starting to play:** Flow asks `Flow.play_tasks()` for what must be ready before a room and runs it here on Play and Sandbox; to load something more before playing (a room's art, a generated level), write a LoadTask and add it there.
  - `display/`: the game window, one autoload, `Display` (`display/display.gd`; owner 2026-10-27). The `fullscreen` action (F11, Alt+Enter) and `toggle_fullscreen()` switch fullscreen on and off anywhere; `is_fullscreen()` reads the window itself. The main menu and the pause menu's Settings page have a switch. On the web the browser allows it only after a key press or click, not a gamepad button.
  - `save/`: reading and writing under `user://` only. `save_file.gd` (`SaveFile`, living staffs H6): one ConfigFile (`user://save.cfg`) of flags, `has_flag`/`set_flag` (written at once), `is_new`, and settings (`get_setting(key, fallback)`, `set_setting(key, value)`, also written at once; the screen shake switch uses one); a missing or broken file is a new save. Runs and unlocks join it in M3.
  - `base/`: base classes (`enemy_base.gd`, `room_base.gd`: small M1 resources with `id` and `demo`) and build info. M2's spell components (part 1) are `spell_component.gd` (`SpellComponent`: `id`, `demo`, `display_name`, `complexity` 1–4, `icon`, `kind()`, `ranges()` and `range_problems()`) and its four kinds `form_base.gd` (`FormBase`), `element_base.gd` (`ElementBase`), `modifier_base.gd` (`ModifierBase`) and `trigger_base.gd` (`TriggerBase`), each documenting its fields and allowed ranges; the element reactions are `reaction_table.gd` (`ReactionTable`, `find(status_id, element_id)`) of `reaction_row.gd` rows (`content/spells/reactions.tres` holds six reactions as twelve rows, one per direction), which have no `id`, so the registry never takes them for content. M1's `SpellBase` is gone (M2 part 11): the one way to fire is `Spells.cast_staff(player, staff, origin, direction, mana)`, which returns the mana spent or `REFUSED`. Players and bots call it and read no spell field; `tests/core/test_spell_field_reads.gd` fails when a script outside `content/spells/`, `core/base/` and `core/spells/` does. **Staffs rework (A3, docs/milestones/M2-staffs.md):** a fifth card kind, `multicast_base.gd` (`MulticastBase`: `extra_draws`, `mode` TOGETHER, SCATTER or BURST, `repeats`, `repeat_interval`, `mana_cost`, `cooldown`); the carrier a form fires, by name (`FormBase.carrier`: &"atom" to &"slam", each a script in `spells/carriers/`; `carries_payload()` for a rain), modifier behaviours (SHIELD to RELAY, `behaviour_strength` up to 256) and trigger events (BLOCK to ALLY), each commented with the kit that runs it; and `staff_base.gd` (`StaffBase`: `id`, `display_name`, `slots`, `draw`, `cast_delay`, `recharge`, `spread`, `ranges()`, `range_problems()`), which is not a card: staffs live in `content/wizard/staffs/`. `build_info.gd` holds the build info.
  - `story/`: `story_validator.gd` (`StoryValidator`, M2 part 23) checks lore files (`check_lore`, `check_component_lore`, `format`) and returns problems like `SpellValidator`. The registry reads `content/story/lore/**.json` on every scan: `get_lore(&"component", id)` gives the text or "", `validate_story()` the problems (also a missing lore file for any spell component), `warn_story_problems()` pushes them in a debug build.
  - `spells/` (staffs A4; staff codes D2: `staff_code.gd` (`StaffCode`) writes and reads a staff as `sm1:` plus its card ids, and `Spells.staff_code` and `Spells.parse_staff_code` check them against the registry; text only): `Spells.compile_staff(cards, staff)` reads a staff's cards into a `CompiledStaff` (`compiled_staff.gd`: the `casts` of one cycle, every compiled spell in `nodes`, and the `wasted` cards, slot -> true) with `staff_compiler.gd` (`StaffCompiler`, the reading rules of docs/milestones/M2-staffs.md); each `CompiledCast` (`compiled_cast.gd`) has its `group` (`CompiledGroup`: `spells`, `scatter`, `repeats`), the slots it read, `mana`, `delay`, `recharges`, `wrapped`, `targets` (what each card attached to) and a plain `description`. **Wasted triggers (rules R2b):** a trigger whose event never happens on its carrier is listed in `wasted` (`Carrier.fires_with`, from what each trigger needs in `TriggerBase.NEEDS`: on hit, on kill and on reaction on carriers that hit (a decoy or familiar only with a blast, whose hits are its hits), timer and on hurt on every carrier that lasts, not on a slam or teleport, which are over at once (rules R4d), on wall only on flying shots and beams, on block wherever a shield or deflect runs, so not on a rain or familiar), as is one missing the card its event needs (on block a shield or deflect, on reaction an infusion or relay, on kill and on reaction on a carrier that hits nothing itself a blast, on wall no ghost on a flying shot). Its payload is still read, so the cards after it read in the same order, but it is not attached: each of its cards is wasted ("Nothing casts it") and costs no mana or time. A compiled spell now also has `fallback` (on the caster or on a payload's origin), `element_ids`, `behaviours` (summed strength per `ModifierBase.Behaviour`), `payload`, `own_payload`, `node` and `slot`. **Spell names (E1):** `spell_namer.gd` (`SpellNamer`, made by the compiler) gives each `CompiledCast` a `spell_name` from its cards: modifiers are adjectives (the first three), infusions fuse into one word, a trigger's word and the plural of its payload follow "of", multicast cards are hyphenated prefixes ("Twice-Seeking Firefrost Bolt of Sudden Novas"; a plain bolt is "Bolt"). The words are the card's `name_words` (`SpellComponent`; empty falls back to `display_name`); a card with several words has one picked by a stable hash of its own id, so the same cards always give the same name and editing other cards never rewords it; a name says at most 3 carriers per group ("and more"), 2 payload levels and 90 characters. `Spells.staff_view(cards, staff)` gives the builder plain values (each cast has its `name`; and hands `staff` back, so a builder can preview other cards in the same staff). **The staff runtime (A5):** `spells.gd` (the `Spells` autoload, class `SpellRuntime`) casts. **Carriers** (`carriers/`, docs/CARRIERS.md): each carrier is a `Carrier` script known by its name (`CarrierAtom`, `CarrierBeam`, ... found by `Carriers.of(&"beam")`, the `carrier` a form card names) that answers yes/no questions about itself (`traits()`: does it fly, hit, last, move its caster...); each card says what it needs from a carrier (`ModifierBase.NEEDS`, `TriggerBase.NEEDS`), and which cards do nothing on a carrier, with the builder's sentence, is worked out from the two (`tests/core/test_card_rules.gd` checks it by playing every card on every carrier); the compiler asks them, and the runtime makes its own bound set (`Carriers.make_all`) and hands each launch to its carrier (`launch`, `shoot`, `on_hit`, `on_move_end`, `step`, ...), so `spells.gd` never asks which carrier a spell has and names none. A carrier asks the runtime for the rest only through `carrier_kit.gd` (`CarrierKit`: the cast under way, the aim, the shot kit, the hit path, payloads, live carriers, moves, entities), never through `Spells`' own members. The beam, swing and slam carriers keep rows of their own; `staff_poses.gd` (`StaffPoses`) plays the staff animations. Every hit with no shot slot (a beam's, a sweep's, a strike's, a zap, a jump) goes back through `Spells` as one `RayHit` (`ray_hit.gd`), so cards, payloads and chains have one path; the looks read the carriers' rows from `Spells.carrier(id)` (typed: `CarrierBeam.of(spells)`, `CarrierSwing`, `CarrierSlam`, and `CarrierDash`, `CarrierDecoy` for the body and `ai`) and the staff animations from `poses()`. `install_staff(player, staff, compiled)` makes a compiled staff the build of one of a player's four staffs (a new generation; editing switches its sustained carriers off) and `cast_staff(player, staff, origin, direction, mana)` fires the next cast of its cycle, returns the mana spent or `REFUSED`, and moves the cursor (`cast_index`) and the delay (`cooldown_left`; the staff's `recharge` after the last cast). Tags (`SpellTag`, one caster field since actors G2) are staff (bits 0–1), generation (2–4), node (5–13: the compiled spell's index, up to 511) and caster (14–23: 0–1023, every actor id) under `FLAG` (bit 24), clear of the enemy attack tags and below `SpellTag.LIMIT` (`1 << 29`): `make(caster, staff, node, generation)`, `caster_of`. The caster is the actor id (actors G3b); the old wrappers (`make_for`, `make_enemy`, `is_enemy_tag`, `player_of`, `row_of`) are gone. A shot with `arc` zaps the nearest body of another team in its reach on a clock, the first zap ready at once and each later one an interval after the last, never on the body its shot hits next (`first_on_path`; owner, 2026-10-30) (`_step_arcs`, `_zap`: a short ray with the shot's `arc_hit`, using its trigger fires, so `on hit` goes off); `return` is a modifier behaviour. A group's carriers leave along one aim; every shot is then turned up to its staff's `spread` degrees (times its modifiers' `spread_mult`) either side, at random from the cast's seeded generator; a payload fires as a group under its spells' own tags; a fallback strikes everything where it lands, the caster too (`Spells._strike_round`; each body a `projectile_hit` of its tag, rules R4 F2). A `hold` carrier lives `HOLD_LIFETIME` and reserves the cast's mana (`mana_reserved`, `reserved_mana`) until the staff is cast again (that press casts nothing and returns 0.0; the caller decides which presses may), edited, or its last shot ends (`is_holding`). A held rain or swing, over at once, is cast again every `wind_up` + `lifetime` along the wizard's aim now (`_repeats`: a rain falls again, a swing sweeps back), and its hold ends only when switched off. A `hold` carrier in a payload is the same hold, switched on when it fires: one rule for every firing (`_start_hold`). Its firings share one tag, so the staff reserves its cast's mana once; one from a build that is no longer the staff's (edited, or its caster closed) is no hold and lives its own lifetime. The recipe path is gone (staffs A6c): staffs are the one way to build and cast. **Multicast spread (B2b):** a `scatter` group sends each carrier in a random direction from a generator seeded by player, staff and cast count (the same cast scatters the same way); a `burst` group fires `repeats` times, `repeat_interval` seconds apart (at once for 0) at the mana of one cast; `echo` fires the carrier once more after its strength in seconds at half damage (`CompiledSpell.echo_hit`, the whole hit scaled by `HitProfile.scaled`: heal, slam, every status and the kind kept; its zaps `echo_arc_hit`; no second echo; on a `hold` carrier a second held copy, switched off with it and reserving nothing more); `mirror` fires the carrier again with its aim reversed: every carrier but a dash or teleport, whose mirror is wasted ("a move and its mirror cancel"; rules R4g). **Swings (melee I2):** a swing carrier (`CarrierSwing.start`, rows beside the live beams that grow as needed, `SWING_ROWS_START`) leans back for its `wind_up`, then sweeps its `arc` round the wizard's hand (`set_aim`'s `pivot`; the tip without one) out to its `ray_length` in its `lifetime`, centred on the aim locked at the cast and following the hand; each step it strikes every body in the wedge it turned through since the last (`Projectiles.sweep`, then `strike`, in the beam hit context, so payloads and chains work), each body once, outward from the hand (so knockback pushes straight out; a carrier's own `knockback` replaces `KNOCKBACK`); swings turn clockwise and back by turns per caster, the swings of one cast the same way, and one within `SWING_CHAIN` of the last sweep's end has no wind-up; its `blast` and `on expire` happen where the arc ends (`swing_end_point`). **Staff animations:** every carrier card's `staff_pose` (keys in its wind-up, strike, a looping hold and after: turn, lift, push, glow, stretch, shake, land, mood; FormBase documents them, the validator checks them, the compiler packs them once, `FormBase.packed_pose`) is played for the body of an actor's own cast: `staff_pose`, `staff_glow`, `staff_glow_tint`, `staff_stretch`, `staff_shake`, `staff_mood`, `staff_land` and `staff_land_point` (how far its tip lands on the point its carrier strikes, from the hand: `Carrier.strike_point` for a carrier that `STRIKES_POINT`, a slam, stopped at a wall; `land_at` moves it, the slam's impact) and `staff_pose_dir` (zero while none plays; the aim of the cast for a swing or slam, which lock it, else the live aim); a new animation starts from where the last one has the staff, a lasting carrier's strike (a beam's, rain's or dash's life) ends with its last shot, and the looks draw it (gameplay/actor's `ActorLook`; zero otherwise) for the look; `swing_slots`, `swing_on`, `swing_origin`, `swing_dir`, `swing_side`, `swing_turned`, `swing_arc`, `swing_reach` give the live swings for Feel. **Payload and line carriers (B2c):** `rain` sends a `form_shown` cue `&"rain"` (its `length` is the seconds until it falls) and after its `lifetime` strikes every body within `RAIN_SPLASH` of the aim point (`ray_length` or `RAIN_REACH` ahead, stopped at a wall) with its own hit and cards, in the beam context `_on_hit` reads (`CarrierRain.land`; an echo's at half), then drops its payload there and fires its own `on expire` trigger (rules R4g); `familiar` and `decoy` send `entity_spawn_requested` (INF seconds for `hold`) a step ahead along the aim, twice the card's size (where it is cast when a wall is in the way), as a rune is placed (`_placed_at`; so a mirror's copy is behind, rules R4 F3), count each entity as a live shot of their tag until `entity_ended`; a familiar has no payload of its own and casts what its triggers give it (`timer · familiar · bolt` casts a bolt from it every tick, from its wizard's body along the aim at the cast; rules R4 F3), guard a decoy whose card has a shield or deflect (Entities asks `guard_decoy` every step: other teams' shots near it are deflected, or stopped while its charges last, each a block; the swing's `_guard`), and fire an entity's `on expire` payload and `blast` (`Spells._blast`) at its end point; a `hold` switch-off, a rebuild or a revoked build sends `entity_end_requested`; `wall` is one solid still shot its `ray_length` ahead (`WALL_REACH` without one), a row of `shots` stones across the aim `spread` pixels apart (`Projectiles.set_solid`, rules R4 F6): a wall while it lives (shots end on it or bounce off it, ghost passes, its own payloads leave it, bodies cannot walk through it: a static body on the walls' layer), it hurts what touches it along its row and its hits never spend it (pierce is wasted on it), a shield or deflect on it guards its whole row, and homing makes it creep as one piece as a rune does; `reach` multiplies a flying shot's `lifetime` and every other carrier's `ray_length` (wasted where `Carrier.reaches` is false: rune, orbit, decoy, familiar). **Cards on rays (rules R4f):** a chain jump of a ray pierces as its carrier does (its pierce); ghost takes a beam through walls for its whole length (`ray`'s `ghost`); magnet on a live beam pulls toward its line every step (`pull_requested` for each piece of its path, with both ends); growth widens a live beam's hits by its factor every second it is on (`beam_growth`; Feel draws it as wide); spiral waves a live beam's path sideways, a sine of `BEAM_WAVE` pixels sampled `BEAM_WAVE_STEPS` points a wave (`_wave`), from its staff and again from every turn at a wall (`_beam_steer`). **Moves, areas and refunds (B2d):** `dash` and `teleport` ask the body to move (`caster_move_requested` carries each move's way and distance; a teleport goes along the aim and is cut at the first wall; a dash the wizard casts itself takes the way it walks in place of the aim, `cast_staff`'s `walk`; `mirror` fires a move back the other way too, and the two add up to none); every hit of a carrier with `pull` asks the caster to move to the hit (the old Hook carrier is `pull · bolt`, rules R4 F1; a blast's hits move nothing), a `swap` hit moves the target to the caster (`target_move_requested`) and the caster to the target; `recoil` pushes the caster back `strength` pixels from each firing of the cast (`mirror` cancels it); every move adds up, on the body as on a shot (rules R4 F1: a recoil longer than a teleport takes it back past its start, two pulls add, two dashes stack); a dash strikes every body its mover passes once (`PASS_REACH`) and a teleport the bodies where it lands (`LAND_REACH`), so hit cards and hit triggers work on them; a move's `shield` guards what it moves (the wizard by a barrier, a shot by shield charges; dash, teleport, pull, swap); a dash, teleport, pull or swap cast by a point moves the wizard (to the point, or to the hit; rules R4c, F1); `caster_move_finished` for a dash or teleport, and for a pull whose hit spent its shot, is the carrier's end point (its `blast` and `on expire` payload; a shot with pierce left ends where its flight ends, so `on expire` fires once, rules R4a); a spent, expired or beam-ending shot with `blast` explodes there (`cue_shown`) and strikes everything round it, its caster too, through the one strike every area uses (`Spells._strike`: swing, slam, dash, teleport, rain, blast and the cards that land on a point), so each body it catches is a hit of the carrier with its hit cards and triggers, and its hits blast no more (rules R4 F2); `siphon` sends `mana_refund_requested` per hit. The later firings wait in a queue that grows as needed (nothing is dropped for room) and start from where the caster has moved to; a rebuild drops the cast's own (those the wizard casts: a burst's repeats, an echo, a rain, whose timer ends with its landing, a waiting `on cast`), while a waiting payload of a shot or a point keeps its build, as a shot in the air does, and fires; a `hold` switch-off drops only the waiting firings of its hold carriers (rules R4a). **Casters are actors (actors G3b):** every caster number in Spells is an actor id (`core/actors`): the per-caster arrays are sized `Actors.ACTORS`, a body opens its caster with `open_caster(id)` (a clean row) and closes it with `close_caster(id)` (its staffs emptied, its own waiting launches, holds and beams ended; its shots in the air fly on, and their waiting payloads fire on, as after an edit; rules R4 F4), and the caster-keyed events name the id.   - `projectiles/`: the projectile manager, one autoload, `Projectiles` (`projectiles/projectile_manager.gd`). Projectiles are rows in packed arrays, not nodes: `spawn(caster, position, velocity, lifetime, radius, hit_layers, pierce, tag)` starts one, and the manager moves them all in `_physics_process` and draws them all in one `MultiMeshInstance2D`. Things that can be hit are Node2Ds registered with `add_target(node, radius, layer, owner)` (`LAYER_ENEMY`, `LAYER_PLAYER`; a target's `owner` actor is never hit by that actor's shots); every shot hits both layers, whoever cast it (actors G3c: no friendly-fire or enemy-fire flag any more), its own caster's targets excepted; a spatial grid of the targets keeps hit tests cheap, and the path of each step is checked as a segment and the search widens with the largest target radius, so neither fast shots nor big targets are missed; a piercing shot hits every target its path passes in a step, nearest first, and a target once while it touches it: it hits it again only after it has left it (owner, 2026-10-29; an orbit ring hits a target each time it comes round). Its memory is a list per shot through one growing pool; a hit test marks the remembered targets first, so it costs the targets touched plus those remembered. A hit sends `projectile_hit(caster, target, position, tag, shot)` (`tag` is the int given to `spawn`, for looking up damage) and ends the projectile unless it has `pierce` left (a piercing shot hits up to 3 targets per step); damage is `combat`'s job. The target is picked at random among those in reach (seeded, so a replay picks the same) and kept while it stays in reach, alive and not just hit, so a fan of homing shots spreads over a group. `homing_point(caster, origin, direction, max_angle, layers, within, keep, pick_seed)` is the same pick for anything else (a cone of `max_angle`, PI for any way; `homing_target` is the id to pass back as `keep`): `homing_aim` bends a beam's or teleport's way with it, `home_velocity` turns a moving thing at a turn rate (a dash, whether it moves a shot through `move_shot(slot, offset, seconds, turn_rate, within)` or the player), and `turned_toward` is the one turn they all share. Outside the manager, a homing thing holds a `Homing` (`spells/homing.gd`: its spell's turn, reach and bend, the target it keeps and its seed) and calls `steer`, `point` or `aim`; a beam's legs, a teleport and the player's dash (`CarrierDash.of(spells).move_homing`, read by the player) do. There is no default range: the spell runtime passes `CompiledSpell.homing_range`, set by `Carrier.homing_range` from the Homing card's `behaviour_reach` (a beam or teleport at least as far as it goes; a rain and a wall are placed on a target that near their aim point, `CarrierRain._homed_place`, rules R4i; 0 where homing cannot steer, an orbit, a swing, a slam, a decoy, a familiar, and the card is wasted). `remove_by_tag(tag)` quietly removes every shot with a tag; `exclude(slot, node, seconds)` keeps one shot from hitting one target for a while; `freeze_shot(slot, seconds)` is a local stop (Feel's hit-stop, melee I7): the shot holds where it is, keeps its life and tests no hits while every other shot flies on (`S_FROZEN`; `freeze_left_of`); the manager's own signal `shot_ended(tag)` is sent once for every tagged shot that ends (hit, life, wall, bounds, cap drop, `clear`; after the shot's event handlers, so they can spawn children first; not for `remove_by_tag`); every event of a shot names its slot as its last argument, `shot` (`projectile_hit`, `projectile_expired`, `shot_blocked`, `shot_deflected`, `wall_met`; -1 for a ray), and combat hands it on with what the hit sets off (`kill_landed`, `reaction_landed`, `hit_landed`, `reaction_triggered`, `enemy_died`), and a blast's strikes are hits of its carrier; nothing reads a "current shot" from the manager. Read per-shot state with `get_seq_of`, `get_tag_of`, `get_velocity_of`, `get_life_of`; `get_anchor(caster)` reads what the manager knows. `ray(caster, origin, direction, length, pierce, layers, tag, width, exclude)` is the beam (with a last `ghost` argument, on `ray` and `ray_points`, it passes through walls; as long as `length` says, its wall walk covering all of it; not charged to the hit-work budget): no row, it stops at a wall, sends `projectile_impact` and `projectile_hit` for the nearest `pierce + 1` targets and returns how far it got (a handler may fire another ray, as deep as the payloads go; the scratch of each nesting level, the hits a ray keeps and its path grow as needed, so nothing caps a ray's hits, length, turns or depth); with a last `bounces` argument (on `ray`, `ray_points` and `ray_curve`; no cap: it turns as often as it has bounces and length) it turns at a wall as a bouncing shot does (`_bounced`, the face rule they share) and goes on for the length it has left, straight, or along `ray_points`' `steer` (the spell runtime's `_beam_steer`: a homing beam homes again from every turn, a spiral one waves again), sending a wall impact at every turn, and `ray_path` / `ray_path_count` hold the path it walked to `ray_end` (the spell runtime gives `bounce · beam` its bounce cards' count, and draws a live beam along that path); `ray_curve(caster, origin, bend, end, ...)` is the same along a bent beam (8 pieces), and with `hit` false only finds how far it gets; both leave `ray_end` and `ray_end_heading`. `sweep(caster, origin, direction, side, from_angle, to_angle, reach, layers, exclude)` finds (sends nothing) every body whose hit circle reaches into a wedge round `origin` (radians off `direction`, `side` 1 clockwise on screen), out to `reach`, with no wall between: `sweep_nodes`, `sweep_points` (where the wedge meets each, on its line from `origin`) and `sweep_heads` (the sweep's way there), which grow as needed; `strike(caster, target, point, heading, tag, form)` sends one instant hit's `projectile_impact` and `projectile_hit` (a swing's). Each shot has a caster (`set_caster_shot`, `set_caster_point`, `get_caster_of`, `caster_shot_of`, `is_cast_by_wizard`): its caster's anchor by default, which an orbit circles and a returning shot comes back to (a homing one still homes on the way back: its way home bends toward its target at the homing rate, never more than `RETURN_BEND`, 60°, off the line to its caster, so it always gets closer and never circles; rules R4a; the way home takes no life, so it always comes home unless its caster's anchor is gone; rules R4 F4); `move_shot(slot, offset, seconds)` moves a shot on top of its own motion (a payload's dash, pull or recoil); the moves on a shot add up, each on its own time, as the wizard's pushes do (so a payload's `mirror · recoil` cancels, and a hook after a recoil gets both; a blink keeps the moves under way; rules R1e). `nearest_target(point, radius, layers, exclude, exclude_also)` (it leaves the target's hit circle centre in `nearest_point`) and `targets_in(point, radius, layers, out, to)` search the target grid for targets whose hit circle overlaps a circle (or, with `to`, comes within `radius` of the line to it: a beam's magnet; chain, homing and area effects use them; nothing is allocated if `out` is reused). Just before each `projectile_hit`, and whenever a shot ends on a wall or pillar (target `null`), it sends `projectile_impact(caster, target, position, direction)` for looks only: where the shot stopped and the unit vector it flew (`gameplay/feel` turns it into a spray or stone chips). Walls: `set_walls(rects)`, `add_wall_body(body)` (rectangle shapes of a static body; `flow` calls it for the room) and `clear_walls()` fill a grid of 8 px cells (`set_bounds` clears it); a shot whose path enters a solid cell ends there, piercing ones too (unless it has bounces left or is a ghost), counted in `wall_hits` (a fast shot still hits a target in front of the wall; a walk is capped at 64 cells; `spawn` refuses a shot born inside a room wall without taking a slot); `set_solid(slot, across, stones, gap)` makes a still shot a wall while it lives (rules R4 F6: its row lies in the grid as a count on top of the room's mark, `ROOM_CELL`, and as a `StaticBody2D` on `WALL_LAYER`, both following it when it creeps or grows and gone when it ends; it hits along its row; a shot it cast leaves it; another team's shot that meets it is turned or stopped by its deflect or shield, `_solid_guard`), and `clip_to_walls(from, to)` shortens a segment to the first wall (a path of at most one cell each way whose corner cells are clear is answered without the walk), `place_caster(caster, anchor, from, to)` is `set_anchor` and `clip_to_walls` in one call (every actor's Caster, when its body moved), and `circle_blocked(center, radius)` says whether a circle is out of the bounds or touches a wall (a teleport checks the body with it). A target's team is its owner actor's (`set_target_owner(node, actor)`), or its layer's for a target no actor owns. Each actor has an anchor (`set_anchor`) for its orbit shots. A player's shot is built by the shot shaders (below) on a pixel grid, in three batches (bolts, runes, orbit shots; staffs B6a; the enemy ramp's flying shots and runes in two more): a small core shaped by its body kind (`KIND_BOLT`, `KIND_RUNE`, `KIND_ORBIT`) in the palette ramp of the colour set with `set_core(slot, color)` (the spell runtime passes the first infusion's tint; white when unset, which draws in its caster's ramp; `get_core_of(slot)` reads it), white-hot at its heart, a long tail behind a bolt or orbit shot that cools and frays, a soft glow round both (premultiplied blending: the shot's pixels opaque, the glow added), and particles given off from its tail in the styles of all its cards, mixed at random, set with `set_look(slot, look)` (`pack_look(kinds)` packs `LOOK_*` kinds as a set of bits; the runtime passes `CompiledSpell.look`), drawn about `look_size(radius)` (one-pixel lines at every zoom); so a shot shows who fired it and which cards it carries. **Trails (the owner, 2026-10-28):** a flying shot keeps the last `TRAIL_SAMPLES` points of its path (one every `TRAIL_EVERY` seconds, and at every bounce, blink and end) in a row of one data texture, and `shot_trail.gdshader` leaves its tail pixels and card particles in the world along that path, so the tail follows a homing, orbiting or bouncing path instead of turning with the shot, each pixel cools in its own time, and the trail outlives its shot by `TRAIL_KEEP` seconds, cooling where it ended (`drawn_trails` counts those). Nothing allocates per frame. Behaviours that act only at a wall or a hit (bounce, ghost, sticky before it sticks, self-hit, pierce) have no pass.

Then a test of its own, copied from one of `tests/core/test_projectiles_kit.gd` (`_test_spiral_weaves_round_its_line`), and the spell runtime's call of the setter (`Spells._apply_travel`, from the compiled card numbers). `test_projectiles_step_exact.gd` must still pass unchanged: a new behaviour changes nothing for shots without it.

What they share is in includes: `shot_palette.gdshaderinc` (the palette ramps P_SHADOW/P_BASE/P_LIGHT and the enemy ramp, the materials, the look kinds `L_*`, the effect kinds `K_*` and flags, `bit_set`, `falloff`, `hash_seeded` and the kind/code decoding), `shot_look.gdshaderinc` (the shared uniforms `sim_time` and `glow_strength`, the look varyings and `look_of`/`look_from_color`/`SET_LOOK`: player, zoom, ramp, the emitting kinds; `hash`, `emitter`, `ramp`) and `shot_particle.gdshaderinc` (a card's particle round a body: `place_particle` works out once where it is and what it looks like, `particle_pixel` colours a pixel of it, `particle` does both for the shaders that still loop per pixel). **A trail's particles are geometry** (`ProjectileManager.trail_mesh()`, `TRAIL_QUADS`): one instance per trail of a mesh of small quads, each told in its UV its kind (`TRAIL_Q_*`: the core's light, a piece's tail light, a particle's light, a particle, a tail pixel, a step of lightning's jagged line, the core) and its slot (a moment back from now, a pixel back along the path, a piece); the vertex shader works out from `trail_data` what that slot is now (a binary search finds the piece a moment or a pixel is on) and puts its quad round it alone, or folds it away, so the fragment stage only colours a pixel of its own quad. The lights are drawn first (added; the head's first, for void's dark heart), then the pixels, oldest first and the core last. The particle kinds are data, not code: a row each in the shader's LOOK TABLE (life, start, throw, drag, curl, float, circle, line, blink, colours, light, rate; plus a dash's streaks and feet), read by one routine (`spark`), so a new kind is a new row. A slot has room for `TRAIL_SPARKS` moments (a second), `TRAIL_TAIL_PIXELS` pixels of tail (a faster shot's tail loses its oldest end) and `TRAIL_JAGS` steps of lightning. **Effects and beams are geometry too** (2026-10-29): Feel draws an effect as an instance of `Feel.effect_mesh()` (its light, 12 card particles, 16 sparks, a poof's 4 clouds, its flash: cross, dotted disc, fraying ring) and a beam as `Feel.beam_mesh()` (a light and a pixel quad per piece of its path, its splash's sparks and their lights, 12 card particles), each quad told its kind and slot in its UV as the trail's are; the shapes are worked out in `vertex()` (`place_particle` for a card's particle) and the fragment stage colours a pixel of its own quad. A bent beam's pieces each keep to their side of the bend (cut at the bend's middle), so its glow is not doubled there. **Every shader is compiled before the first room** (`projectiles/shader_warmup.gd`, a LoadTask Flow runs behind the loading screen on the first Play of a session, `loading/`): it draws each shader once, one a unit (a frame), the way the game draws it (BATCH a `MultiMeshInstance2D`, MESH a `MeshInstance2D`, RECT a sprite or Control), putting nothing on the screen, and Godot's own canvas shader too; `warmed` stays true for the session. The shot shaders are listed there; an area hands its own shader over with `ShaderWarmup.want(shader, how)` where it first uses it (an autoload's `_ready`, or the node's `_init`). `tests/core/test_shader_warmup.gd` fails for any `.gdshader` in the project that is not warmed. **To add a draw kind:** a new `.gdshader` in `projectiles/` (listed in `shader_warmup.gd` by how it is drawn) that includes the palette (and the look and particles if it needs them), its own batch or node made with that shader, and its instance data in the encoding above (`look_color`, the kind and code in the custom data's alpha). **Rules:** keep each shader to its own kind (no mode switches between unrelated looks); no per-pixel loop over a path's history or over all of anything that grows (a pixel loops only over a small fixed number, a shot's 12 particles); keep each fragment stage small and branch-light: Windows browsers compile WebGL through Direct3D, and a big branchy fragment shader can take ~90 s to compile and crash the browser's GPU process (it did: the trail's, 2026-10-29), so particles are geometry placed by `vertex()` and looks are data (a table row), not a branch per kind; the vertex stage compiles through Direct3D too, so keep it straight-line where it can be (no big nested loops), and call a loop (a search of the path) from one place only: the compiler builds a function's loop again for every place it is called from (`samples_before` searches two keys at once so the trail calls it once); work that is the same for a whole instance goes in `vertex()`; and a fragment's light is added (alpha 0) while its pixels are opaque (premultiplied blending). Headless Chrome and CI (SwiftShader) never show a slow compile: a shader change that grows a stage is checked on a real Windows GPU (docs/DECISIONS.md, 2026-10-29, "Trail particles as geometry").

  - `pools/`: object pools; no per-frame allocations. `pools/pool.gd` is a fixed-size pool typed by its factory Callable: it makes every object up front, `acquire()` returns an object or `null` when all are out (it never grows), `release()` takes one back (a double or foreign release is refused), and optional `on_acquire` and `on_release` hooks reset state. `clear()` frees every object, including ones still handed out, so drop your references first. Pools are for nodes and effects (enemies, damage numbers); projectiles are packed-array rows and do not use them. Use `preload("res://core/pools/pool.gd")`.
