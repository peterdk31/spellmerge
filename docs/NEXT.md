# Next

The ordered task queue for the current milestone, M1 (its design, [M1-core-loop.md](milestones/M1-core-loop.md), is the plan for every task below; M0's [dry runs](milestones/M0-foundation.md#dry-runs) carry over). The first unchecked task under "Queue" is next. Bug reports go above features. Claude keeps this file up to date; only tasks in paths Claude may change belong here (docs/PLAN.md, "Path tiers").

## Queue

- [ ] **Event bus and base classes (M1 part 1).** Build `core/events` (one autoload, a typed signal per event, player index first; names from `gameplay/README.md`) and `core/base` (the small spell, enemy and room base resources, with the `demo` flag), register the autoload in `project.godot`, add tests in `tests/core/`, then make `core/events` the source of truth: fix the "Events at a glance" table and every area README's event lists to match, and remove the "provisional" marks. First example: `core/events/events.gd`.
- [ ] **Style and the first placeholder assets (M1 part 2).** Write `docs/STYLE.md` (palette, light from top-left, 1px outline, max 3 shades, frame counts, 32×32 grid) and add it to `llms.txt`. Make hand-written SVG placeholders with manifest entries (`origin: ai`, tier `placeholder`, tool and prompt): a floor and a wall tile, a wizard idle sprite in four player colours, one enemy sprite, a fire bolt and a hit spark. Add placeholder `.ogg` cast and hit sounds if a session can produce them; otherwise list them in `docs/BACKLOG.md`. Update the Art and Audio READMEs' "Example to copy" with the real paths. First examples: `art/tilesets/` and `art/vfx/` (Art), `audio/sfx/` (Audio).
- [ ] **Input and per-player focus (M1 part 3).** Build `core/input` (join by button press, one device per player, P1 keyboard and mouse or gamepad, P2–P4 gamepads, leave, virtual devices for bots, actions for move, dodge, cast and overlay) and `core/ui_focus` (each panel takes input only from its owner), with tests for all four indices. Add the input actions to `project.godot`. First example: `core/input/input_manager.gd`.
- [ ] **Pools and the projectile manager (M1 part 4).** Build `core/pools` (generic typed pool, no per-frame allocation) and `core/projectiles` (bulk simulation, one batched draw, spatial grid, a global cap that degrades gracefully, `projectile_hit` events), with tests for the cap, for reuse and for 1,000 projectiles. First example: `core/pools/pool.gd`.
- [ ] **Registry (M1 part 5).** Build `core/registry`: scan the content folders at start, return resources by folder and id, honour the `demo` flag; everything else loads with literal paths. Test with a fixture folder under `tests/core/`. First example: `core/registry/registry.gd`.
- [ ] **Player (M1 part 6).** Build `gameplay/player/player.gd` and the wizard scene in `content/wizard/` (placeholder sprite): move, dodge with brief invulnerability, cast, mana, health, downed and revive, for any index 0–3, using `core/input` and sending `spell_cast`, `player_downed` and `player_revived`. Tests with two indices at once. Update the player and wizard READMEs with the real example paths. First example: `content/wizard/base/`.
- [ ] **Combat, the fire bolt and one enemy (M1 part 7).** Build `gameplay/combat/combat.gd` (damage pipeline, hit and hurt boxes, knockback, `damage_dealt`, `enemy_died`), a minimal `gameplay/ai/ai.gd` (chase and one telegraphed attack), the fire bolt in `content/spells/` and one enemy in `content/enemies/`, using pools and the projectile manager. Tests for damage, knockback and death. Update the spells, enemies, combat and ai READMEs with the real example paths. First examples: `content/spells/forms/bolt/` and `content/enemies/<name>/`.
- [ ] **The room and arena glue (M1 part 8).** Build one room in `content/rooms/` with space for four, spawns and doors, and a minimal `gameplay/flow/flow.gd` slice (load the room, spawn the wave, send `room_entered` and `room_cleared`, restart in under 3 seconds when all players are down, first room within 10 seconds of start). Add a Play button to the main menu that starts it. Update the rooms and flow READMEs. This is the first playable build and starts the weekly playtest. First example: `content/rooms/<biome>/`.
- [ ] **Feel (M1 part 9).** Build `gameplay/feel/feel.gd`: hit-stop (short, the same for every player), screen shake with a setting to turn it off, and hit particles and sounds on every hit within particle limits, driven only by `damage_dealt`, `enemy_died` and `player_downed`. Test that it never changes damage. Update the feel README. First example: `gameplay/feel/presets/`.
- [ ] **Co-op (M1 part 10).** Build `gameplay/coop/coop.gd`: join and leave mid-run on a button press, the friendly-fire option (default off), the shared camera that zooms out to fit all players, `player_joined` and `player_left`. Tests for every join order of 1–4 players. Update the coop README. First example: `gameplay/coop/coop.gd`.
- [ ] **Per-player HUD (M1 part 11).** Build `hud/theme` (the single theme) and `hud/panels` (a corner panel per player in their colour with health and mana, and an overlay that opens on a button, never pauses the game and sends `build_change_requested` as a stub), all on `core/ui_focus`. Readable at 640×360 with four panels. Update the HUD README. First example: `hud/panels/player_panel/`.
- [ ] **Bots and the 4-bot smoke test (M1 part 12).** Build `tests/bots/` (a bot that plays through virtual devices and the real input path) and `tests/smoke/four_bot_smoke.gd`: four bots join and clear the room, bot 4 idles in its overlay the whole time, and the test fails unless the others finish and no error is logged. Run it in the editor and in the Linux export through `ci/build/build.sh`; if that needs an owner-only change, file it in `docs/BACKLOG.md`. First example: `tests/smoke/boot_smoke.gd`.
- [ ] **Performance probe and budgets (M1 part 13).** Add `tests/benchmark/` with a probe that runs inside the 4-bot test and logs frame time and node, projectile and memory counts; it gates nothing yet. Check web build size and load time against the budgets in docs/PLAN.md and record the numbers in `docs/LOG.md`. Add a per-effect particle limit constant with a test.
- [ ] **Web 4-bot run (M1 part 14).** Write the exact change `ci/smbot/websmoke.py` needs to run the 4-bot test in headless Chrome (how the game is told to start it, without `JavaScriptBridge`) under "Needs an owner decision" in `docs/BACKLOG.md`, and make the game side ready. If the owner hasn't made the change, report the task blocked so the next one goes on.
- [ ] **Starter kit sources and Style Guide content (M1 part 15).** In `art/` add the kit's source files that sessions can write: palette files (a GIMP `.gpl` and a hex list), 32×32 grid and sheet templates as SVG, golden-example candidates, and a one-page checklist in `docs/STYLE.md`. Write in `docs/BACKLOG.md` what the owner must add to `ci/smbot/site.py` to build the Style Guide page and the zip.
- [ ] **Stabilisation and checkpoint C1 (M1 part 16).** Fix every open bug in M1's scope and tune the wave and feel values from bot logs and playtest answers. Then prepare the C1 issue: a build link, an honest assessment, the question "do moving, dodging and casting feel good, alone and with 4 players?" and the verdicts go, iterate and pivot. Default to iterate after 7 days without an answer.
