## Queue

- [ ] **Event bus and base classes (M1 part 1).** Build `core/events` (one autoload, a typed signal per event, player index first; names from `gameplay/README.md`) and `core/base` (the small spell, enemy and room base resources, with the `demo` flag), register the autoload in `project.godot`, and add tests in `tests/core/`. First examples: `core/events/events.gd` and `core/base/spell_base.gd`.
- [ ] **Event lists reconciled (M1 part 2).** Docs only. Make `core/events` the source of truth: fix the "Events at a glance" table in `gameplay/README.md` and every area README's event lists to match it, and remove the "provisional" marks.
- [ ] **Style document (M1 part 3).** Write `docs/STYLE.md` (palette, light from top-left, 1px outline, max 3 shades, frame counts, 32×32 grid) and add it to `llms.txt`.
- [ ] **Placeholder art (M1 part 4).** Hand-written SVGs with manifest entries (`origin: ai`, tier `placeholder`, tool and prompt): floor and wall tiles in `art/tilesets/crypt/`, a wizard idle sprite in four player colours in `content/wizard/base/`, the enemy sprite in `content/enemies/ember_imp/`, a fire bolt and a hit spark in `art/vfx/`. Update the Art README's "Example to copy" with the real path. No sounds: they are Audio contributors' work; list the cast, hit and enemy-death sounds under "Audio needs" in `docs/BACKLOG.md` so the weekly run opens `now` issues for them, and leave the Audio README's example as it is until the first one merges.
- [ ] **Input and per-player focus (M1 part 5).** Build `core/input` (join by button press, one device per player, P1 keyboard and mouse or gamepad, P2–P4 gamepads, leave, virtual devices for bots, actions for move, dodge, cast and overlay) and `core/ui_focus` (each panel takes input only from its owner), with tests for all four indices. Add the input actions to `project.godot`. First example: `core/input/input_manager.gd`.
- [ ] **Pools and the projectile manager (M1 part 6).** Build `core/pools` (generic typed pool, no per-frame allocation) and `core/projectiles` (bulk simulation, one batched draw, spatial grid, a global cap that degrades gracefully, `projectile_hit` events), with tests for the cap, for reuse and for 1,000 projectiles. First example: `core/pools/pool.gd`.
- [ ] **Registry (M1 part 7).** Build `core/registry`: scan the content folders at start, return resources by folder and id, honour the `demo` flag; everything else loads with literal paths. Test with a fixture folder under `tests/core/`. First example: `core/registry/registry.gd`.
- [ ] **Player (M1 part 8).** Build `gameplay/player/player.gd` and the wizard scene in `content/wizard/base/` (the part 4 sprite): move, dodge with brief invulnerability, mana, health, downed and revive, and cast by calling a single cast method on the equipped spell and reading none of its fields. It works for any index 0–3, uses `core/input`, and sends `spell_cast`, `player_downed` and `player_revived`. Tests with two indices at once. Add `.tscn` to the allowed files in `content/wizard/README.md` and rewrite the allowed-files paragraph of `gameplay/README.md` to say that `gameplay/` is script-only and scenes live in `content/` and `hud/`. Update the player and wizard READMEs with the real example paths.
- [ ] **Combat and the enemy (M1 part 9).** Build `gameplay/combat/combat.gd` (damage pipeline, hit and hurt boxes, knockback, `damage_dealt`, `enemy_died`) and a minimal `gameplay/ai/ai.gd` (chase and one telegraphed attack), and the enemy `content/enemies/ember_imp/` (`.tres` on the enemy base class, scene, using the part 4 sprite). Tests for damage, knockback and death. Update the enemies, combat and ai READMEs with the real example paths.
- [ ] **The fire bolt and projectile hookup (M1 part 10).** Build the bolt in `content/spells/forms/bolt/` (a `.tres` on the spell base class), fired through `core/pools` and `core/projectiles`, hitting through the damage pipeline. Done when: the bolt hits and kills the enemy in a test; the player and the bots only call the cast method and a test fails if any script outside `content/spells/` and `core/base/` reads a spell field. Update the spells README with the real example path.
- [ ] **The room (M1 part 11).** Build `content/rooms/crypt/arena_01.tscn` (layout only, no scripts, tiles from part 4) with space for four, four spawn points, enemy spawn points and doors, plus its `.tres` on the room base class. Update the rooms README with the real example path.
- [ ] **Arena glue (M1 part 12).** Build a minimal `gameplay/flow/flow.gd` slice: load the room, spawn the wave (fixed, sized for four players), send `room_entered` and `room_cleared`, restart in under 3 seconds when all players are down, first room within 10 seconds of start. Add a Play button to the main menu that starts it. Update the flow README. This is the first internal playable build; the owner playtest does not start yet.
- [ ] **Feel (M1 part 13).** Build `gameplay/feel/feel.gd`: hit-stop (short, the same for every player), screen shake with a setting to turn it off, and hit particles and, if the sound file exists, a hit sound on every hit (a missing sound is silent, never an error), driven only by `damage_dealt`, `enemy_died` and `player_downed`. Add the per-effect particle limit constant and a test that the limit holds with four players. Test that feel never changes damage. Create `gameplay/feel/presets/` with the first preset and point the feel README at it.
- [ ] **Co-op (M1 part 14).** Build `gameplay/coop/coop.gd`: join and leave mid-run on a button press, the friendly-fire option (default off), the shared camera that zooms out to fit all players, `player_joined` and `player_left`. Tests for every join order of 1–4 players. Update the coop README. First example: `gameplay/coop/coop.gd`.
- [ ] **Per-player HUD (M1 part 15).** Build `hud/theme` (the single theme) and `hud/panels` (a corner panel per player in their colour with health and mana, and an overlay that opens on a button, never pauses the game and sends `build_change_requested` as a stub), all on `core/ui_focus`. Readable at 640×360 with four panels. Update the HUD README. First example: `hud/panels/player_panel/`. When this is merged, the weekly run starts the "Playtest of the week" issues.
- [ ] **Bots and the 4-bot smoke test (M1 part 16).** Build `tests/bots/` (a bot that plays through virtual devices and the real input path, calling only the cast method) and `tests/smoke/four_bot_smoke.gd`: four bots join and clear the room, bot 4 idles in its overlay the whole time, and the test fails unless the others finish and no error is logged. Run it in the editor. First example: `tests/smoke/boot_smoke.gd`.
- [ ] **The 4-bot test in the Linux export (M1 part 17).** Run the 4-bot test in the Linux export through `ci/build/build.sh`. If that needs an owner-only change, write the exact change under "Needs an owner decision" in `docs/BACKLOG.md`.
- [ ] **Performance probe and budgets (M1 part 18).** Add `tests/benchmark/` with a probe that runs inside the 4-bot test and logs frame time and node, projectile and memory counts, and reads the particle limit constant from part 13; it gates nothing yet. Check web build size and load time against the budgets in docs/PLAN.md and record the numbers in `docs/LOG.md`.
- [ ] **Web 4-bot run (M1 part 19).** Write the exact change `ci/smbot/websmoke.py` needs to run the 4-bot test in headless Chrome (how the game is told to start it, without `JavaScriptBridge`) under "Needs an owner decision" in `docs/BACKLOG.md`, open one issue labelled `owner` with the same text, and make the game side ready. If the owner hasn't made the change, report the task blocked so the next one goes on; the weekly run repeats the request until it is done.
- [ ] **Starter kit sources and Style Guide content (M1 part 20).** In `art/` add the kit's source files that sessions can write: palette files (a GIMP `.gpl` and a hex list), 32×32 grid and sheet templates as SVG, golden-example candidates, and a one-page checklist in `docs/STYLE.md`. Write in `docs/BACKLOG.md` what the owner must add to `ci/smbot/site.py` to build the Style Guide page and the zip, and open one issue labelled `owner` with the same text.
- [ ] **Stabilisation and checkpoint C1 (M1 part 21).** Fix every open bug in M1's scope and tune the wave and feel values from bot logs and playtest answers. Then prepare the C1 issue: a build link, an honest assessment, any owner items still open listed first, the question "do moving, dodging and casting feel good, alone and with 4 players?" and the verdicts go, iterate and pivot.
