# Flow

## Purpose

Room sequence, door voting, transitions and waiting for builders.

Built in M3 (see "Gameplay sub-areas" in docs/PLAN.md).

Players in the spell builder never block the others: the rest keep playing.

## Contract

- **Public entry script:** `gameplay/flow/flow.gd`. Other code uses only this script and the events it sends and listens to; nothing else in the folder is public. It is the autoload `Flow` (registered in `project.godot`).
- **What exists (M1 slice):** on `play_requested` it begins the run `run_id_to_play` (default `crypt`, `DEFAULT_RUN_ID`; a run definition of content/runs), whose first room and enemies the run area names from its map (below; players come from `wizard_scene`) and the hands of the run's mode (`staffs_for_mode()`, owner 2026-11-01: one staff file per setup, used as it is, never copied or changed, in every build channel): in Play and the hub the first two basic staffs of `STARTER_HEADS`, curl on RB and star on RT, each its own head, and the other two hands empty (`START_HANDS`, items I2: players start with two staffs; moon and crystal wait for the items); all from `wizard` in the registry; a missing one starts no run: it logs a warning and stays idle). `start_cards` are four lists of card ids (default: A `dash`, X `bolt`, Y and B empty); **each mode's setup** (owner, 2026-11-05): with its staffs and start cards a new wizard gets its mode's card bag, counted (`bag_for_mode()`, card id to copies, through `seat_wizard`; items I3): Play `play_bag` (`PLAY_BAG`: one `dash`, one `bolt`, an entry a copy), the hub `Inventory.DEV_COPIES` (20) of every spell card of the registry, the start cards coming with their staffs beside it (a wizard made again from its loadout holds that loadout's bag instead, items I4); every player gets the staffs and copies of the cards and builds them itself, so flow holds no spell (staffs A6a), and builds one world node (room scene, a camera, a player for every player slot that has a device, the enemies the map puts in the room) that becomes the current scene. It sends `room_entered`, and `room_cleared` when the last enemy of the room has died. When every player is down the run ends after `RESTART_DELAY` (1.5 seconds), back in the hub (connected biomes CB7, decision 14; a run of `play_requested` too since CB8, where it once began a new run): a new world, full health, no shots left. A player who leaves and rejoins mid-run gets the start staffs again. The end also comes when the last enemy dies after everyone is down. Play with the mouse joins the keyboard as P1 only when nobody has joined; anyone already joined (for example a gamepad) plays as they are. A second `play_requested` while a run is on is ignored. `stop_run()` ends the run (tests use it). Mid-run joins and leaves: on `player_joined` a player is added at the room's spawn for joiners of that slot (`RoomBase.joiner_spawns`), else at the player spawn farthest from danger, on `player_left` it is removed (the camera, which `coop` drives, has limits set to the room). The exits between rooms come in run generation RG4; door voting and the rest of the run lifecycle in M3. `run_started` and `door_vote_requested` are not used yet.
- **The intro (living staffs H6, `intro.gd`):** on a new save (`save`, a `SaveFile`, without the `INTRO_SEEN` flag) `play_requested` shows the intro first (state `INTRO`, the node `Intro` as the current scene; `wants_intro()`, `play_intro(requester)`): one staff dropped per joined player (`drops()`, `drop_time`, `hit_time`), `LENGTH` 14.5 s whatever the number of players. Any joined player's accept, back, pause or staff button skips it at once for everyone (press counts, so no tap is lost); played out or skipped, the save gets `INTRO_SEEN` and the run starts as above. Flow's `step` steps it, so tests drive it with fixed deltas. It plays only for people: `intro_enabled` is false when a test script is the main loop or the game was started with user arguments (`--four-bot`, `--stress`, the timing run); a test switches it on with a save of its own. `stop_run()` ends an intro too. Its captions are in `intro.gd` until `content/story` has a schema for cutscenes (M3).
- **A run (run generation RG3; a biome since connected biomes CB8, docs/milestones/connected-biomes.md):** a run of `MODE_RUN` is a run definition's (`run_id_to_play`); after `Tick.begin_run` deals its seed, Flow sends `run_begun(run_id, players)` (the seats joined at its start, which the map is made for; run generation RG5), and the run area (gameplay/run, `Run`) makes the run's biome map and answers with each room's fight (`run_room_filled`: its enemies, scale and pace, kept as a `RoomFight`) and the map (`run_biome_chosen`, a copy kept as the world's state), which `start_run` lays and plays (`_begin_run_of_rooms`, then "Room life" below). Flow never makes the map: those events are all it knows of the run. A run the registry lacks, or one its content cannot make (`Registry.run_problems`), starts nothing, refused before anything goes; a run whose map cannot be made for its seed (no answer) is found once the last world went, so Flow is idle, and a run from the hub's stone goes back to the hub. **Rooms hold layout only:** what fights in a room is the map's. Every run ends back in the hub, lost (everyone down) or won (the portal home): `play_requested`'s too. (The row map's run of rooms, its lit exits, `run_way_taken` and `_enter_next_room`, and the hub's lectern with its start depth went with CB8.)
- **A room's fight (boss OB2a, docs/milestones/boss-old-broom.md, decisions 30 and 31; no waves):** a run's room holds the enemies the run's map puts in it (ids of `EnemyBase.FOLDERS`, enemies and bosses, one per body; an id the registry lacks stands nothing, with a warning), each told to difficulty before it enters the tree (`enemy_standing`: scaled to the room, run generation RG5). A boss stands at once at the enemy spawns, so its intro opens on a body that is there and drawn. Every other enemy **spawns in** (enemy spawning EA3, docs/milestones/enemy-spawning.md: `_stand_enemy` sets `Actor.spawn(style.seconds, style.id)` before it enters the tree, for room enemies and a phase's adds alike, with the style `spawn_style_for(data)` picks: `SpawnStyle.pick` from the registry, the enemy and the room's biome (spawn styles AS2: the enemy's own, else the biome's, else `rise`, else `SpawnStyle.DEFAULT`'s), so it is not there yet while Feel draws a mark and its body rising out of it), and they come **in groups as the room gets quiet** (EA5, the owner's answers of 2026-11-17: no timer, groups by cost): each fight's queue (`RoomFight.queue`, a `RoomSpawning`, `room_spawning.gd`, pure rules, Flow's state, saved in snapshots) holds it, at the pace the run tells with the room's fight (`run_room_filled`'s `group`, `refill_at` and `stagger`, costs worked out by the run from its biome's `SpawnRules`; all zero: the whole list at once). A group takes ids from the front of the list until its cost (`EnemyBase.cost`) reaches `group`, always one at least; its bodies start `stagger` seconds apart; the first group starts as the fight does (`_call_room_spawning`); the next only once the current one has all started and the cost standing or spawning drops to `refill_at` or below (`_standing_cost`), however long that takes. A group takes the enemy spawns farthest from every standing wizard first (`RoomSpawning.rank`, worked out as its first body stands), never one over a hole nor one within `RoomSpawning.NEAR` (64 px) of a wizard (unless every spawn is that near: then the farthest alone), round them in turn, stacked where one is used again within the group (`stacked_position`), each spot moved to the nearest clear ground (the projectile manager's `nearest_ground`: a stacked body never stands in a wall or over a hole's edge). An id that cannot stand is dropped from the queue, and the room is checked every tick the queue is open, so it is never stuck uncleared. One still spawning or still to come is one of the room's (`enemies_left`), so the room can't be cleared before then. `stand_all_now()` calls the rest of the queue at once (tests: `tests/support/spawning.gd`). The room plays `cue_shown` `room_start` (`ROOM_START_CUE`) on every wizard. When the queue is empty and the last is down, `room_cleared` (a room the run puts nothing in is cleared as it starts). The run's last room (no way on: the boss's, or the deepest fight of a run with no boss) cleared wins the run, and `RUN_WON_DELAY` (2 s) later it ends as a lost one does: from the hub's stone back to the hub, from `play_requested` a new run. Everyone down first keeps that end's time.
- **A phase's adds and health by the players (boss plan OB13, docs/milestones/boss-old-broom.md, "Phase adds and player-count scaling"):** every enemy Flow stands is counted for the wizards in play (`Actor.players`, before it stands; `EnemyBase.health_per_player`), and counted again as a wizard joins or leaves (`Actor.count_players`: its most and its health change by the same share). A body's phase asks for its adds on the bus (`adds_requested`, from its `Phases`): Flow stands them for a body it stood (`_stand_enemy`, as the room's own: counted, told to difficulty by `enemy_standing`, among the room's fight), as many as the entry (`EnemyAdds`) names for the wizards in play, under its cap of those of the entry alive, on a ring round the body slid out against the walls and blocking props (`RoomAdds.ring`, the room grid's `slide_body`, `Projectiles.grid()`) or at the room's enemy spawns in turn. `adds` (`RoomAdds`, `room_adds.gd`) keeps each add's caller and entry. When the caller dies its adds crumble at Flow's next step (one still spawning at the first step after it lands), each through Combat (`crumble_requested`: nobody's kill, its death told as any other), so the room is cleared after the last; an add Combat cannot crumble, or one gone with no death told, is forgotten then. Each call's ring is turned by the adds stood before (`RoomAdds.RING_TURN`), so waves stand apart.
- **A boss's intro (docs/milestones/boss-intro.md, step BI2):** as a biome room's fight starts (`_open_biome_boss_intro`, once its bosses stand and the room is announced), the first boss with an intro (`EnemyBase.boss_intro`, a `BossIntro`) among the room's own enemies opens it when the run's rules have intros on (`SessionRules.boss_intros`): `boss_intro` (`BossIntroHold`, gameplay/flow/boss_intro_hold.gd; its members state, its boss a REF) stops the game (`Sim.stop(&"boss_intro")`) and sends `boss_intro_opened(actor, boss_name, lore, intro, page, fresh)`. Never in the hub, never for a phase's adds, never twice in a room. The command `boss_intro_next_requested(player, page)` (any seat's A on a page written out, from the HUD) turns the page only while `page` is still the page, so two seats pressing on one tick turn one (`boss_intro_paged`); past the last page the stop is let go and `boss_intro_closed(actor)` sent (another stop, a pause menu or a waited-for pad, still stands until it ends). It closes by itself when its boss leaves the tree (`_watch_boss_intro`, a step that runs through the intro's stop, since Flow's own does not step while the game is stopped) and when the last seat leaves; it is cleared with the room's enemies (`_forget_enemies`: the next room, the run's end). As it closes, the presses carried through the ticks it stood still and those of its last tick are dropped (`Frames.drop_presses`), so a staff pressed during it casts nothing as the fight starts, and a staff still held then is not held until it is let go (`Sim.held_through`; a keyboard's Space is A and staff 1). A snapshot restores it; its `rebuild_derived` sends `boss_intro_opened` again, not fresh, or `boss_intro_closed` with no actor when none is open. Intros are off for automation: where `intro_enabled` goes off, Flow turns this machine's `boss_intros` off too. Tests: `tests/gameplay/flow/test_boss_intro_hold.gd`.
- **The hub (docs/milestones/online-lobby.md, L1):** `hub_requested` (the main menu's Play) starts a run in the room `hub` (`HUB_ROOM_ID`, content/rooms/hub): an island in the void where players join and leave as they like (`player_joined` / `player_left`, at the room's player spawns, with no join protection there), with Play's two staffs (the `dev` staff on RT went in items I2: the hub's rack, I6, replaces it, its premade staffs built on the `dev` staff, content/items; the sandbox's two showcase builds joined it when the sandbox went, crypt rework CR-S, docs/DECISIONS.md 2026-11-16) and start cards, every card in the bag (owner, 2026-11-11: to try combos online until a better way to come by cards comes; a run from the stone takes that bag along, owner 2026-11-14, items I4), the room's three training dummies (its scene's stand-ins) and no enemies. On a new save the intro plays first, as for `play_requested`. Hits hurt there as anywhere, but a fall costs nothing (owner, 2026-11-13: parties may fight each other and try builds with no consequence): the room's `RoomBase.stand_up_after` (2 seconds) after a wizard is downed it stands up by itself where it fell, at full health and protected for `Downed.JOIN_PROTECTION` (`_stand_up_left`, by seat: state; a teammate's revive, leaving or a new run stops it), and everyone down starts no restart. **The teleporter stone** (a prop of the role `run_start`, stood on where its own area is; props W8c): the hub's rules (`hub`, `HubRules`, gameplay/flow/hub_rules.gd) count the wizards standing on it each tick and whenever one joins or leaves (`standing`, `wizards`: state), `is_stone_lit()` while all of them stand in it, and sends `start_stone_changed(standing, wizards, lit)` when the count differs from what it last sent (`HubRules._stone_sent`, DERIVED: a game whose state a snapshot replaced sends it again); as the hub starts, and (0, 0, false) as it is left. The `run_start` props are asked to enter `lit` or `unlit` with it (`prop_state_requested`; props W8), so the lit look and the `stone_lit` cue are the prop's. **Rooms (props W8c):** a run builds its room's layout once (`RoomBase.build()`) and reads what is where from that instance (`RoomPlaces`); its placements' bodies, props and dummies alike, stand at the run's start in the tree's order (`contents`, `RoomContents`, gameplay/flow/room_contents.gd, which keeps them and answers by kind and role), and a room with the zone `prop_yard` (`ZONE_PROP_YARD`) stands every prop of the registry with no role there (`yard`, `PropYard`), each fresh again `PropYard.RETURN_SECONDS` after it is lit, broken or gone. **Starting:** a seat's A (`accept`) on the lit stone is the command `run_requested` (sent by the HUD's panels, applied at the next tick's start on every machine and in a replay); Flow starts a run (`MODE_RUN`, `run_id_to_play`) if the stone is lit and that seat has a wizard. A joiner puts the stone out before any command of its tick applies. **The whole player carries over** (owner, 2026-11-10; items I4, owner 2026-11-13: what a run's start takes along is the whole player): through the stone, each seat's wizard is made again from its player loadout (`PlayerController.loadout_of`, gathered by `_party_of` as a `PartyLoadout` and handed to `start_run` as `party`; `PlayerController.seat_loadout` seats it): every bag counted as it was, every staff under its number with its cards, and its hands, so an empty hand stays empty (its card bag too: the hub's goes into the run, owner 2026-11-14, replacing "Play's bag again" of 2026-11-11); a seat with no loadout, and a seat that joins mid-run, gets its mode's staffs, start cards and bag, as anywhere. The hub begun anew for a joining machine keeps them too: the game says what a run starting now takes along (`Frames.set_party_source`, `_party_now`: in the hub each seat's loadout, anywhere else nothing), a recording begun writes it into its header (`PartyLoadout`, core/sim), and the hub's start takes it back (`Frames.next_run_party`), so every machine playing that recording builds the same players; during a run it changes nothing. **A seat that joins the hub under way** (a joining machine's player among them) appears beside the altar, at the room's `joiner_spawns` for its seat (online lobby, decision 4; beside it, not on it, so a dash there does not open the room). **No intro under a replay:** a run a replay starts (an online host's among them) never shows it, on a new save either. **Staffs follow the party from the hub into the run and nothing comes back** (owner, 2026-11-10: the hub is the arsenal the right tools for a run are picked from; a run ends lost or won, and back in the hub the party is ready for a new one): the run's end starts the hub with each seat's own staffs, whatever an earlier line here says of staffs kept on the way back. **The return to the hub is a run's start of its own:** Flow ends the run and asks the frames service for `hub_requested` (`Frames.restart`), which sends it as the next step starts; with no frames service (some tests) Flow starts the hub itself.
- **Modes:** `Flow.mode` is the run's mode: `MODE_RUN` (`&"run"`, a run in a biome) or `MODE_HUB` (`&"hub"`); `MODE_RUN` when idle. The hub starts in its own room (`HUB_ROOM_ID`), a run in its map's start room, `staffs_for_mode()` the staffs, `restart_delay()` the delay after everyone is down.
- **A biome laid out (connected biomes CB2, docs/milestones/connected-biomes.md):** `BiomeWorld` (`biome_world.gd`, Flow's helper, as `RoomContents` is) lays a biome's map (`BiomeMap`, gameplay/run: the state) into a world: every room and bridge's layout at its place (its placements, zones and sockets taken out, `RoomPlaces.strip`), rooms first, and the projectile manager's grid over the whole biome (`set_bounds`): every piece's walls and holes, mirrored as the map says (`PieceShape`, core/base), the dark between the pieces a wall (`RoomGrid.wall_outside`), each joined room socket cut open to its edge (`PieceShape.cut_rect`), the bridges' walls over it and a mouth where each bridge meets a room (`PieceShape.mouth_rect`, `RoomGrid.add_mouth`). The nodes and the grid's layers are laid again from the map, never saved: after a restore a world that laid another map lays the restored one (`rebuild_derived`). A mirrored piece's layout carries CB4's mirror meta (`PieceShape.GROUND_MIRROR_META`) for Feel's ground drawing, announced with CB3's room events. Its rooms' contents, room state and room events are CB3's. Each room's layout says its kind for the view (`RoomKind.LAYOUT_META`, CB12). **A bridge's place holds the lips of its rooms past their mouths** (`RoomGrid.add_place`'s `over`, CB8): a body there is on the bridge, so a room is entered only through its mouth (a wizard on the bridge just outside one once started its fight and was sealed out). Tests: `tests/gameplay/flow/test_biome_world.gd` (the test map laid; a wizard walks through its three rooms, a free enemy stops at the first mouth, a shot stops there, an AI's line of fire stops there and sight sees through it; a world that laid another map lays the restored one, the grid the same to the byte).
- **Room life (connected biomes CB3, docs/milestones/connected-biomes.md, "CB3 done"):** `start_biome(requester, map, fights)` starts a run in a biome map a test gives (`MODE_RUN`; a run's own is the run area's, above): `BiomeWorld` lays its map, telling each piece as it is laid (`room_built`, rooms then bridges, by number), each room's bodies stand from its places mirrored and moved (`BiomeWorld.room_places`), and the rooms' state is `life` (`RoomLife`, room_life.gd: each room entered, started, sealed, cleared, its `RoomFight`; each place awake or asleep). A room's fight starts as a wizard's own body first stands in it (`room_entered` of its number): its bosses stand, the rest spawn in at its pace at its own spawns, its mouths seal one way (`RoomGrid.set_sealed`; nothing inside leaves, a wizard outside walks in), and with nothing left it must beat (an enemy no seat drives, by `Actor.room`) it is cleared (`room_cleared`) and opens. A place sleeps while no body that acts and no shot is in it (`RoomLife.wake`, `Actors.asleep`: the Tick and Combat skip its bodies, its queue waits). Everyone down ends the run back in the hub (connected biomes CB7, decision 14). A later room's placed enemies (an `EnemyStandIn`) stand as it is first entered (`RoomContents.stand_enemies`, CB8), not with the world. Tests: `tests/gameplay/flow/test_room_life.gd`.
- **Gather doors and the run's end (connected biomes CB7, docs/milestones/connected-biomes.md, "CB7 done"):** `gates` (`GatherDoors`, gather_doors.gd: state) holds a biome's gated rooms, by their kind's `RoomKind.door`: each mouth where a bridge meets one is a door, shut to everything (`RoomGrid.shut_mouth`: a room wall over the mouth cell, so the native kernels read it unchanged) until it opens, laid again from the state after a restore. A wizard is at a door on its bridge, or on the gated room's lip outside the shut mouth (a gated room is entered only once it opened). A **gather door** (`gather`, a challenge room's; CB11 gives the kind) opens when there is a standing wizard and every one is at it; the standing ones come in together onto its player spawns (a downed one stays out, for the fight's clear). **The gate** (`gate`, the boss's room) also stays shut while any sealed fight holds a wizard, downed or standing (`held`), and when it opens everyone comes, downed or far away (a downed one stays down for a revive). Each standing one is protected for a moment and the room is entered at once: its fight starts and seals, and **its boss's intro opens** (`_open_biome_boss_intro`, as a row room's, stopping the game for everyone until any seat's A moves it on). A room whose kind has `portal_home` (the boss's), cleared, opens **the portal home** on its floor (its template's zone `portal`, else its middle, on clear ground; a 48 px square): every standing wizard in it wins the run, back to the hub (`_take_portal_home`, as a row run from the stone ends). The view is told each door as it changes (`gather_door_shown`, Feel's `gather_door_looks.gd`). Tests: `tests/gameplay/flow/test_gather_doors.gd`, and the party through the gate played twice and through a snapshot in `test_content_determinism.gd`.
- **Special rooms (connected biomes CB11, docs/milestones/connected-biomes.md, "CB11 done"):** a room's kind says what it is (`_kind_of`, the registry's `RoomKind`). **Its rewards:** a room cleared whose kind names a reward table (`RoomKind.rewards`) sends `room_rewards_due` with it right after `room_cleared`, however its foes left it (the owner, 2026-11-19); the Rewards area rolls each player's offer. **A shop or a fountain** (`RoomKind.FILL_SHOP`, `FILL_FOUNTAIN`), entered for the first time, sends `special_room_opened` with where its shelf (its template's zones `shelf`, else three spots round its middle) or its pool (its zone `fountain`, else round its middle) is (`SpecialPlaces`, special_places.gd); the Rewards area keeps the shelf and the pool. **Locks** (`locks`, `LockDoors`, lock_doors.gd: state, beside `gates`): a key room's (`RoomKind.DOOR_KEY`, a treasure room) and a secret room's (`DOOR_SECRET`) mouths are shut as a gated room's, laid again after a restore. A key room's key drops in the room its bridge hangs off as that room is cleared (its zone `key`, else its middle, on clear ground); the first standing wizard whose feet reach it takes it for the party, and a standing wizard at the key room's door with it held opens the room for all (the key spent). A secret room's element is rolled as the biome begins (the run's chance, `SECRET_PURPOSE`, keyed by the room, among every element card of the registry); that element touching the floor (`floor_touched`) within `LockDoors.TOUCH_REACH` of its rock breaks it open. The view is told each key door, rock and key (`key_door_shown`, `secret_rock_shown`, `key_shown`). **Elites** (decision 24): a fight's enemies come with their elite cards (`run_room_filled`'s `elites`, `RoomFight.elites`, carried through the queue, `RoomSpawning.card`); an elite stands with its card (`Actor.elite_card`), which gives it a slot more and the card in front of its own (`Caster.hold_staffs`), its outline (`EliteLook`) and, through Difficulty, more health. Tests: `tests/gameplay/flow/test_special_rooms.gd`, and a shop bought from and a fountain drawn on twice and through a snapshot in `test_content_determinism.gd`.
- **Room size:** `room_size(room, layout)` (static): at least 640×360, every spawn and door a tile in, and the room scene's `Floor` sprite when it has one. The camera's limits and the projectile bounds (plus `PROJECTILE_MARGIN`) follow it.
- **Known gaps:** no reward rooms yet (M3); the numbers are constants in `flow.gd`, tuned at C1.
- **Dependency direction:** `core` ← `gameplay` ← `content`. This area may use `core/` and the registry. `core/` never depends on it, and content never reaches into it.
- **Events** (`core/events/events.gd` owns the definitions; this list matches it and the table in [gameplay/README.md](../README.md)):
  - Sends: `boss_intro_opened`, `boss_intro_paged`, `boss_intro_closed` (a boss's intro, `BossIntroHold`), `crumble_requested` (an add whose caller died, boss plan OB13; Combat kills it), `room_built` (ground cover GC2: a room's layout laid out, a biome's every piece too, at a run's start, each room entered and a snapshot restored into another room, from `_lay_out`; sent before the placements and zones are taken out, so the cover's fields are still in it, and before the layout joins the tree; a restore into the room shown sends nothing), `run_begun` (a run begins, with its players; the run area answers), `enemy_standing` (an enemy or boss about to stand: difficulty scales it), `room_left` (a world goes: Spells ends what was cast in it), `gather_door_shown` (a biome's gather doors, gate and portal home, for the view; CB7), `key_door_shown`, `secret_rock_shown` and `key_shown` (a biome's key doors, secret rocks and keys, for the view; CB11), `room_entered`, `room_cleared`, `room_rewards_due` (a cleared room's kind's reward table, for the Rewards area; CB11), `special_room_opened` (a shop's shelf or a fountain's pool, for the Rewards area; CB11), `cue_shown` `room_start` (`ROOM_START_CUE`, on every standing wizard as a run's room starts, as its actor; S6, item 13), `start_stone_changed` (and `cue_shown` `stone_lit` at the stone as it lights, as no actor), `door_voted`.
  - Listens to: `run_room_filled` and `run_biome_chosen` (the run area's answer: each room's fight, then the map), `adds_requested` (a body's phase calls its adds, boss plan OB13), `floor_touched` (a secret rock's element, CB11), `enemy_died`, `run_started`, `player_downed`, `player_joined`, `player_left`, and from the HUD `play_requested`, `hub_requested`, `run_requested` and `boss_intro_next_requested` (commands), `main_menu_requested` (this machine back to the main menu, not a command: `stop_run`) and `door_vote_requested` (`door_voted` is flow's announced result of the vote; `room_entered` follows `play_requested`).
- Areas never call each other directly; they talk through events. [gameplay/README.md](../README.md) has the rules every sub-area shares.

## Review questions

A good PR here changes room order, door voting or transitions, and keeps the no-waiting pillar: one player in the builder never stalls the rest. Besides the general review:

- Does a player idling in the builder block anyone? Does voting work for 1–4 players?
- Does it keep to the dependency direction, without calling another area directly?
