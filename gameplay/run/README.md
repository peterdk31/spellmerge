# Run

## Purpose

Run lifecycle: start, seed, end and the summary screen.

Built in M3 (see "Gameplay sub-areas" in docs/PLAN.md).

A run has one seed, so the same seed gives the same rooms and rolls.

Run generation ([docs/milestones/run-generation.md](../../docs/milestones/run-generation.md)) builds it early: RG2 brings the map and its generator; RG3 the area itself (`run.gd`), which makes the map at the run's start and fills the rooms from it; RG4 the way on through it; RG5 each room's scale; RG6 the rule changes a save unlocks.

## The area (run generation RG3; a biome's map since connected biomes CB8)

- **`run.gd`, the autoload `Run`:** when Flow begins a run (`run_begun(run_id, players)`, sent on the run's fresh state, after `Tick.begin_run` dealt its seed, with the seats joined at its start), it makes the biome map of the run definition `run_id` (registry folder `runs`, content/runs) from the content there is (`Registry.run_content()`), its first biome's templates' shapes (`Registry.run_shapes`), the run's chance (`Sim.found`) and its players, once (`BiomeGenerator.generate`, below), and answers: the run's own changes of the run stats (`run_stats_ruled`, connected biomes CB10), then each room's fight (`run_room_filled(room, enemies, scale, group, refill_at, stagger, elites)`: its enemy and boss ids, one per body, its scale, its pace and each enemy's elite card, connected biomes CB11), room by room, then the map itself (`run_biome_chosen(map)`, a copy), which Flow lays and plays. Rooms hold layout only: what fights in a room is the map's.
- **Scaling (RG5):** each room's depth level (`BiomeMap.room_levels`, `level_of`: its scale with one player, by depth only), which an enemy's aim sharpens by (`AimTuning`, gameplay/ai/README.md "Aim"; the owner, 2026-11-19: more players never sharpen it). Each room's scale (`BiomeMap.room_scales`) is the run definition's `scaling` (`RunScaling.room_scale`, core/base: a curve per depth, from the start room to the rules' `scale_depth`, deeper rooms keeping its end, times one per extra player, from one to four), worked out by the generator from the room's depth (bridges from the start room) and the run's players. It grows the room's enemy budget (`RunScaling.scaled_budget`) there, and every enemy's and boss's health through the difficulty area (gameplay/difficulty), which hears it from Flow as each enemy of that room's fight stands (`run_room_scaled`). A wizard joining later plays the map as it was made. **The pace (enemy spawning EA4):** each fight's `group`, `refill_at` and `stagger` are its biome's `MapRules.spawning` (`SpawnRules`, core/base: `group_cost`, `refill_cost`) at the room's scaled budget (`RoomFill.pace`; no spawns: 0s, the whole list at once), plain numbers in `run_room_filled`, never the Resource.
- **State:** `map` (the `BiomeMap`) is the run's state, hashed and saved in snapshots, so a joining machine gets it from the snapshot. It joins the Tick with no step and is renewed at every run's start (`begin_run`, `Tick.RUN_ORDER`): out of a run (the hub) there is no map. Flow keeps a copy of its own as its world's state (`BiomeWorld.map`).
- **Meta progression's hook (RG6):** the map is made by the run definition as the run's unlocks change it (`RunDefinition.changed_by(sim.unlocks)`: each `RunRuleChange` whose save flag they hold, core/base); the generator stays a pure function of what it is handed. The unlocks are the run's start's (`Sim.unlocks`, core/sim/run_unlocks.gd: the host's save, in the replay's header), never this machine's save during a run. The area says which they are on this machine (`unlocks_now`, given to the frames service as its unlocks source, `Frames.set_unlocks_source`): the flags of its save (`save`, a `SaveFile`) that some run definition's rule change names (`RunDefinition.flags`), so nothing else of the save travels.
- **No map:** a definition the registry lacks, or a map that cannot be made (`BiomeMap.not_made`), answers nothing, with a warning saying why; Flow then starts no run (from the hub's stone, the party goes back to the hub).
- **Gone with the row map (CB8):** `RunMap`, `RunNode` and `RunGenerator` (run generation RG2's rows of rooms), the way on by lit exits (`run_way_taken`, RG4), the start depth and the hub's lectern (`RunMap.start_at`, RG7) and the map for the pause menu (`run_map_changed`, RG8; the Y map is CB9's).
- **Tests:** `tests/gameplay/run/test_run.gd` (the map made from the run's seed and every room's fight told before it, a copy; the same seed the same map; renewed at a run's start; the map as state; Flow laying the map the run makes and playing its fights; the map made for the run's players; this machine's unlocks its save's flags a rule change names, and the map made by the rules the run's unlocks leave, a guest's none). A test that plays a room of its choosing pins it as a biome of that room alone (`tests/support/pinned_run.gd`: `MapRules.start_only`).

## The biome map (connected biomes CB2)

- **`BiomeMap`** (`biome_map.gd`, docs/milestones/connected-biomes.md, "The model"): one biome as a continuous world, rooms (a template id, a place on the 32 px grid, a mirroring, a kind) and bridges (a walkway template, its place and mirroring, and the room sockets its sockets 0 and 1 meet: `bridge_ends`), and each room's depth, the fewest bridges from room 0 (`work_out_depths`). Plain packed rows, the state as `RunMap` is: about a kilobyte for twelve rooms, hashed and snapshotted as it is, so a joining machine never makes its own. `problems(shapes)` names what breaks its rules (places on the grid, templates known and of the right kind, each in its mirroring keeping `PieceShape`'s rules, sockets that meet at one point facing each other, a socket joined once, rooms apart, a bridge over its own rooms only, every room reached). Made by hand in the tests (`tests/support/biome_maps.gd`: CB2's three-room test map and a twelve-room one) or by the seeded generator (CB5, below), which also fills it: each room's scale (`room_scales`) and enemies (`enemies_of`, `fill_room`), its `style`, and why a map was not made (`not_made`, `is_made`). Flow lays it (`BiomeWorld`, gameplay/flow). Every run's map since CB8.
- **Tests:** `tests/gameplay/run/test_biome_map.gd` (the test maps keep the rules, each rule named when broken, depths, a copy the same map, the map plain state).

## The biome generator (connected biomes CB5)

- **`BiomeGenerator.generate(definition, content, shapes, sim, players)`** (`biome_generator.gd`): one pure function from a run definition (its first biome's `MapRules`), the content (`RunContent`), the templates' shapes (`Registry.piece_shapes(biome)`: id to `PieceShape`), the run's chance and its players to a `BiomeMap`; it reads no node. Its steps (the script's class doc): the room count and a style by weight (`MapStyle`: long, branching, loop, hub and spokes in the crypt's data); the kinds (each line's `least`, its `chance` rooms up to `max_per_run`, the rest the lines with no limit by weight; one of the line that stands deepest, the boss); the way (`way_share` of the rooms, at least `fights_on_way` + 1, fights enough among them, the boss at its end, so deepest); the rooms off it (off a room that is no dead end, shallower than the boss and at a depth its kind takes, by `branch_chain` and `hub_pull`; the rooms that are no dead end first); the loops (`loops` extra bridges between two free sockets a bridge's ends meet, each kept only where the rules still hold, closed as soon as one can be (the depths worked out again); `loop_pull` favours placements that leave one, weighing every template's placements at once); **the extra entrances** (step 5b, the owner, 2026-11-20: "rooms can have multiple entrances, if it makes sense in the layout"): once every room stands, in every style, every two free sockets of two rooms not yet joined that a walkway of the biome spans clear of every other piece are joined, each only where the rules still hold (the boss deepest, fights enough on every way to it, every kind at a depth it takes, a dead end's one bridge, so the locked and gated rooms keep their doors), one at a time, no roll (the first in the order the sockets were freed, the walkway's first mirroring); `joins_left(map, rules, content, shapes)` says how many such joins a map still leaves (none for a made map); the fill (scale by `RunDefinition.biome_room_scale`, a fight's enemies by its scaled budget, the boss's boss: `RoomFill`, shared with the area's pace; elites, CB11: a fight room from `MapRules.elite_depth` on by `elite_chance` has its first enemy an elite, a challenge room's (`RoomKind.FILL_ELITES`) every one, each elite a card of `elite_cards` by chance, kept in `BiomeMap.room_elites`, `elites_of`). A line with no limit fills the rooms past the fixed and chance ones only while a template hosting its kind is left (CB11; counted for each line alone, by the templates that host its kind, so an upper bound where templates host several kinds: an attempt that still runs short is tried again). A room is placed over a free socket of the room it hangs off by a walkway of the biome in any mirroring (straight or a corner: its far end may face any way), a template hosting its kind with a socket facing it in any of its four mirrorings (`room_mirrors`: BiomeWorld lays the mirrored collision and Feel draws the mirrored ground, CB4), never one the biome holds already (the start room excepted), its slab `GAP` clear of every other room and its bridge over its two rooms only; every place on the 32 px grid. Rolls are `sim.chance(&"biome_map", ...)` through `MapDice` (shared with `RunGenerator`); a seed whose shapes leave a room no placement tries again (`ATTEMPTS`), and a map not made says why, as does a definition with problems (`RunDefinition.biome_problems`). `rule_problems(map, rules, content, shapes)` checks a made map against the biome's rules; `fights_on_way` is the fewest fights on any way to the boss.
- **The crypt (CB8):** the crypt's run is made from its own templates: its start room (`crypt_start`), its four fight rooms with two sockets each, the broom's hall with one, and its bridges 96 to 256 px long, so its validator names nothing (`tests/gameplay/run/test_biome_generator.gd`, `test_the_crypt_is_made`). Since CB11 decision 1's 8 to 12 rooms (`scale_depth` 8) with its fixed kinds (a reward room, a shop, a secret room, four fights, the boss) and chance kinds, from the special rooms' templates and two north-south bridges (a walkway is never turned, so without them no map could branch); CB13 adds fight templates. **The start room alone** (`MapRules.start_only`, rooms 0 to 0): its first template hosting the start kind, unmirrored at the origin, filled: a test's pinned room.
- **A reward room's type** (the owner's ask of 2026-11-19, the generator's step 7): each room of a kind with `RoomKind.typed_rewards` (the reward room) gets a `RewardType` (core/base) from its kind's `rewards` table: a line by weight (its item kind), for a card line one of its cards' kinds evenly (in name order), for the element kind one of its element cards (`BiomeGenerator.roll_type`). The tables and the cards are `RunContent`'s (`reward_tables`, `cards`, gathered by `Registry.run_content`); with none, no room is typed. Rolled under `REWARD_PURPOSE` with a key of its own, so no other roll shifts. Kept in the map (`room_reward_items`, `room_reward_card_kinds`, `room_reward_elements`; `reward_type_of`, `type_room`): hashed state like the rest. Flow tells it with `room_rewards_due` and puts it on the room's layout for the view (`RewardType.LAYOUT_META`).
- **The chance rooms' slots** (the owner, 2026-11-19): every chance room's dice are rolled in line order, and the rooms won take the slots left within `rooms_max` line by line, the lines with the fewest chance rooms first (`BiomeGenerator._chance_order`): a rolled challenge room always gets its slot, and the treasure rooms fill what is left.
- **No dead ends** (the owner, 2026-11-20: "Some of the rooms seem to have bridges with dead ends. There should be no dead ends!"): swept over 200 crypt seeds, every generated bridge's two ends meet two rooms' sockets (at one point, facing each other), in the map, in each piece's drawn ground and in the laid grid, and every socket without a bridge stays lip; the generator made none. What read as a dead end was the held Y map drawing a bridge from a seen room into a room it did not draw (gameplay/feel/README.md, "The held Y map"). `test_every_bridge_meets_two_rooms_and_every_doorway_has_a_bridge` keeps it so over 120 seeds (and no doorways a walkway could join left unjoined), and lays three maps to see each joined doorway open and every other socket walled.
- **Tests:** `tests/gameplay/run/test_biome_generator.gd`, on made-up content (`tests/support/made_up_biome.gd`: every kind of decision 1, slabs of many sizes and sockets, bridges 96 to 384 px across and down, and corner walkways): every style's maps over many seeds sound by `BiomeMap.problems` and `rule_problems` (the boss deepest, 4 fights on every way to it, 8 to 12 rooms), the fixed kinds always there and the chance kinds now and then, a template once and every mirroring placed, the styles differing as their weights say, the same seed the same map, the fill and the scaling, the rule changes on the new numbers, the validator naming a run whose content makes no map (the crypt's of today too), and a map of the crypt's own rooms generated and laid by `BiomeWorld`.

## Contract

- **Public entry script:** `gameplay/run/run.gd`, the autoload `Run` (registered in `project.godot`). Other code uses only this script and the events it sends and listens to; nothing else in the folder is public (the map's scripts are its own; tests read them).
- **Dependency direction:** `core` ← `gameplay` ← `content`. This area may use `core/` and the registry. `core/` never depends on it, and content never reaches into it.
- **Events** (`core/events/events.gd` owns the definitions; this list matches it and the table in [gameplay/README.md](../README.md)):
  - Sends: `run_stats_ruled` (CB10), `run_room_filled` and `run_biome_chosen` (CB8); later `run_started` and `run_ended` (M3).
  - Listens to: `run_begun` (from flow, RG3); later `room_cleared`, `player_downed` and `pause_requested` (from the HUD).
- Areas never call each other directly; they talk through events. [gameplay/README.md](../README.md) has the rules every sub-area shares.

## Allowed files

`.gd` and `.tres`, plus `.uid`, `.import` and `.license` files. Limit: 1 MB per file. Typed GDScript only; no banned APIs. The text shared by all sub-areas is in [gameplay/README.md](../README.md).

## Review questions

A good PR here changes how a run starts, ends or is summarised, keeps runs reproducible from their seed, and works for 1–4 players. Besides the general review:

- Is a run reproducible from its seed? Does the summary cover every player and never wait for one?
- Does it keep to the dependency direction, without calling another area directly?
