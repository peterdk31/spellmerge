# HUD

## Purpose

Everything the players see and click: panels, the spell builder UI, menus, shared widgets and the one theme. It must stay readable with 4 players on one screen and fully usable with a gamepad.

## Contract

- **Sub-folders:** `panels/` (per-player panels), `builder/` (the spell builder), `menus/` (main menu, pause, summary), `widgets/` (shared, reusable controls), `theme/` (the single theme).
- **Events both ways.** The HUD listens to state events from `core/events` and shows only what they say. It also sends player-intent events: requests that carry the player index (0–3), never a finished outcome. It never calls gameplay directly; gameplay checks each request, applies or refuses it, and announces the result as a normal state event (docs/DECISIONS.md, "The HUD sends player-intent events"). Dependency direction: `core` ← `gameplay` ← `content`; the HUD sits beside `gameplay` and uses only `core/`.
- **Events the HUD sends** (`core/events/events.gd` owns the definitions): `play_requested`, `sandbox_requested`, `sandbox_action_requested` and `door_vote_requested` (received by `flow`), `friendly_fire_requested` (`coop`), `staff_change_requested`, `card_move_requested` and `staff_cards_requested` (`player`), `reward_pick_requested` (`rewards`) and `pause_requested` (`run`) (table in [gameplay/README.md](../gameplay/README.md)). The HUD is the only sender of these events and sends no state events, so each event keeps one sender. Gameplay areas listen to them.
- **Public entry script:** none for the area as a whole; each scene's root script is its own entry (for example a menu scene's script under `menus/`). Other areas never reach into the HUD.
- Widgets build on `core/ui_focus`, so each panel takes input only from its owner (player index 0–3). Nothing assumes a single player, and a player in the builder never makes anyone else wait.
- Use the shared theme; don't style single controls by hand.
- Accessibility: readable text sizes, no information by colour alone, gamepad navigation everywhere.

- **The theme** is `theme/spellmerge_theme.tres`, set as the project theme (`gui/theme/custom`), so every control uses it. Player colours are type variations: `PlayerPanel1-4` (panel border), `PlayerLabel1-4` (text), plus `HealthBar` and `ManaBar`. Add a new look there, not as an override on one control. Colours are from `docs/STYLE.md`.
- **The panels** (`panels/`): `panels.tscn` is the autoload `Hud`, a `CanvasLayer` with one `player_panel/` per player in a corner (P1 top left, P2 top right, P3 bottom left, P4 bottom right; about 112×55 px each, so four fit a 640×360 view; the background is 60% translucent so a wizard or enemy under a corner panel still shows). It hears `player_joined`, `player_left`, `room_entered`, `player_stats_changed` (from `player`) and `UIFocus.opened`/`closed`, and shows only that. A panel shows for a joined player after the first room; it takes no input. It says "P1".."P4", "HP", "MP" with numbers, "DOWN" at 0 health and "MENU" while that player has a menu open (their builder, or the pause menu they opened; priority DOWN), so nothing is shown by colour alone.
- **The buttons** (owner, 2026-10-26): the staffs are on the shoulders (RB, RT, LB, LT: `staff_1` to `staff_4`), and the face buttons belong to the menus: `accept` (A) activates, `back` (B) goes back and `alternate` (X) is a menu's second action, all through `core/ui_focus`. `panels.gd` reads two buttons itself, from `core/input` press counts (a quick tap is not lost; a slot with no device is ignored): `back` (B; Tab or E) opens the player's builder in play, when they have no menu open (at this poll and the one before, so the B that closes a menu never reopens the builder), are not down and the game is not paused; `pause` (Start; Escape) closes the menu the player has open, or opens the pause menu. Y is free for now.
- **The radial builder** (`builder/radial_builder.gd`, owner 2026-10-26; nodes `Root/Radial1-4`, made by `panels.gd` under the corner panels): a trial beside the list builder. `back` opens it instead of the list builder once the pause menu's Sandbox page says "Builder: Radial" (`builder_options_changed`; the list builder stays the default), and `back` closes it again. It fills its player's quarter round the corner panel: a column under (P1, P2) or over (P3, P4) the corner panel at the screen's edge with the staff tabs between the LB and RB glyphs, the shown staff's slots in five columns (four rows show; more scroll) and three number lines, and the ring beside it with the hint row under it. **The ring** holds the bag, one place per card id and level (with the count and level drawn when there are several or a level above 1): every card grouped by kind with a coloured arc and a gap between kinds ("Ring: Every card"), or one kind at a time with the kind's letters on a row above and the d-pad's left and right (`kind_prev`, `kind_next`) flipping it ("Ring: One kind"); tiles shrink with the count and below 10 px become plain marks. **The right stick** (`PlayerInput.menu_aim`; P1's mouse) points at a card: it pops out with a double gold frame and the pad rumbles once (`PlayerInput.rumble`; a gap rumbles nothing), and the hub in the ring's middle shows its icon, name, kind and `Spells.component_stats`; with nothing pointed at it shows the staff's numbers. Letting go keeps the card. **The left stick** (`menu_move`, with key-repeat; P1's move keys or a click on a slot) moves the gold marker (with corner ticks) through the slots; the pointed card shows faded in the marked slot (a gold caret where a push inserts). **RT** (`staff_2`) puts the card in and moves the marker on: with "Full slot: Push right" (the default) a taken slot and those after it move right, as one `staff_cards_requested`, and a full staff refuses with a note; with "Replace" it is a `staff_change_requested`. **LT** (`staff_4`) takes the marked card out (a push closes the gap); on an empty slot with nothing after it, it takes out the last card before it and the marker steps back ("Undo" in the hint); with push, an empty slot with cards after it closes ("Close gap"). **Hold Y** (`extra`, 0.6 s) clears the staff: a red frame fills round the slots, then every card fades out at once. **LB, RB** switch staffs (UIFocus `paged`). **The numbers** under the slots: "Mana 12%" (the dearest cast of the cycle as a share of the wizard's maximum mana from `player_stats_changed`; red with "!" above 100 %, since it cannot be cast), "Dmg" (the cycle, every shot landing once) and "Time" (the cycle's seconds), each with "> new" in gold for what RT would make of it (the plan's `staff` handed back to `Spells.staff_view`). The hint row shows the RT, LT, Y and B glyphs with their verbs, dimmed when the button would do nothing. It opens through `core/ui_focus` with itself as its one control (capture, the "MENU" word, `back` and paging), reads the rest from `core/input` for its own player only, and closes like the list builder (`pause`, going down, the run ending).
- **The pause menu** (`menus/pause/`, node `Root/PauseMenu` of `panels.tscn`, in the middle of the view): opened by any player's `pause` in a room; it stops the game for everyone (`get_tree().paused`; the HUD, `PlayerInput` and `UIFocus` run while paused) and only the player who opened it works it (its title says "P2 PAUSED" in that player's colour). Pages: the main one ("Resume", "Sandbox" only while `sandbox_changed(true)`, "Settings"); **Sandbox** (staffs B7: "Imp wave" and "Reset dummies" send `sandbox_action_requested(player, imp_wave | reset_dummies)` and stay on the page; the builder switches "Builder: List/Radial", "Ring: Every card/One kind" and "Full slot: Push right/Replace" flip on `accept`, stay on the page and send `builder_options_changed` to `panels.gd`; "Back"); **Settings** ("Gameplay", "Back"); **Gameplay** ("Friendly fire: Off/On" sends `friendly_fire_requested(player, on)` and shows coop's `friendly_fire_changed`, never its own guess; "Back"). `back` goes up a page and resumes from the main page; `pause` again, Resume, the opener's device leaving and the run ending close it, and closing un-pauses. The focused button is marked with "> ". The main menu shows a focused "Sandbox" button above Play in `dev` and `preview` builds (`main_menu.gd`'s `channel`), which sends `sandbox_requested(0)`.
- **The hurt vignette** (`panels/vignette/`, node `Root/Vignette` of `panels.tscn`, created by `panels.gd`): a red glow at the screen edges, strongest toward the corner of the wizard whose health fell, fading in half a second. It comes only from a drop in the health of `player_stats_changed`, takes no input and never covers the panels. A hit adds glow by the share of maximum health it took, and less the more wizards are playing (divided by the square root of their number), so a four-player fight does not keep the screen red; the middle of the screen stays clear. The setting `Hud.get_vignette().enabled = false` turns it off (kept in memory, like `Feel.shake_enabled`; saving it waits for `core/save` and the settings screen).
- **The staff word** (staffs A6a): the corner panel shows "Staff 2" (the staff's number) for the staff the player cast last (from `staff_cast`), nothing before the first cast. There is no swap: every staff has its own button.
- **The wave line:** a "Wave N" label (`Root/Strip/WaveLabel`, 12 px, in the middle of the view left of the break line, no input) set from `wave_started` and shown only while a wave is on: hidden at `room_cleared` (so not during the build break) and when a run starts or ends.
- **The build break line** (M2 part 19; `Root/Strip/BreakRow`, right of the wave line in the same strip, no input): a code-drawn hammer (`widgets/hammer_icon.gd`) and "Build N" (seconds left, rounded up). It shows from `build_break_started(seconds)` and counts down from `_process` (`step_break(delta)`); it is display only, so `Flow` alone decides when the wave starts. Limit: the HUD only knows the break from the event, so a player or HUD that joins mid-break shows no break line until the next one. `wave_started` and a run starting or ending hide it.
- **The staff builder** (`builder/`, staffs A6a and B8; nodes `Root/Builder1-4` of `panels.tscn`): the corner panel expanded toward the middle, beside its player's corner panel (to the right of P1 and P3, to the left of P2 and P4), so four open builders and four corner panels fit 640×360 without covering one another. The title ("P1 Staff 2"), the four staff tabs by number (`1` to `4`: RB, RT, LB, LT on a pad) and `Close`, then two lists in scrolling windows (`widgets/row_window.gd`, 8 rows at a time, 8 px text): the slots of the shown staff ("3 Fire >5" for a card that goes into the carrier in slot 5, "> you" on the caster, "> aim" at the aim point; "5 Bolt #1" for a carrier and its cast; "4 -" for an empty slot; " !" after a card that does nothing where it is; "^" before a card picked up; " <" after the cards linked to the focused one) and the bag ("Empty", then every card, the one in the selected slot marked " *"). Opened by its owner's `back` (B) in play at any time, waves included, and closed by `Close`, by `back` anywhere but on a bag row (there it goes back to the slot), by `pause`, when its owner goes down or when the run ends. The d-pad moves in two dimensions through a navigator given to `core/ui_focus` (tabs in a row, up from a list to the tabs, left and right between the slots and the bag), so every slot is reached with the d-pad alone; LB and RB (`page_prev`, `page_next`) show the previous or next staff. **Pick and place:** `accept` on a slot with a card picks it up, `accept` on another slot (of any staff) places it, swapping, with `card_move_requested(player, from staff, from slot, to staff, to slot)`; `accept` on the bag while holding, or `alternate` on a slot, sends the card back to the bag (to staff -1); `back` drops it where it was. With nothing held, activating an empty slot selects it and moves focus to the bag, and activating a bag card sends `staff_change_requested(player, staff, slot, id)` and selects the next slot, so a staff is still built left to right by picking cards one after another. **Player 1's mouse:** a click works as `accept`, a drag from a slot to a slot (or to the bag), or from the bag to a slot, moves the card (only builder 1's buttons take the mouse). It never changes what it shows by itself: the picture follows `staff_changed(player, staff, plan)` (the plain `Spells.staff_view`: `cards`, `casts`, `wasted`) and `bag_changed` from `player`. **The info panel** (`Info`, a top-level child, 112×112 px, in the free strip of the player's quarter) shows the cast plan (one line per cast of the staff's cycle, from the plan, its words then its damage if every shot lands once, the plan's `damage`) and a note: "Refused: <reason>" after a `build_refused`, else "Does nothing: <reason>" for a wasted card in the focused slot, else where the focused card goes ("Goes into Bolt (slot 2).") and its description (`Spells.component_description`); its last line is a hint for the focused control (`widgets/hint_line.gd`: the glyph of the button, then the verb). **Show buttons, not action names** (owner, #4): use `widgets/action_glyph.gd`, never the words "Cast" or "Dash". Buttons use the `BuilderButton` theme variation; the one in focus takes `BuilderButtonFocus` besides the "> " mark.
- Events the HUD listens to: `player_joined`, `player_left`, `room_entered`, `wave_started`, `build_break_started`, `player_stats_changed`, `run_started`, `run_ended`, `staff_changed`, `bag_changed`, `build_refused` (the builders; the radial builder also `player_stats_changed` for the wizard's maximum mana), `staff_cast` (the corner panel shows the staff cast last), `room_cleared`, `sandbox_changed` and `friendly_fire_changed` (the pause menu) and `UIFocus` signals. Events it sends: `staff_change_requested` and `card_move_requested` (the builders), `staff_cards_requested` (the radial builder), `sandbox_action_requested` and `friendly_fire_requested` (the pause menu).

## Allowed files

`.gd`, `.tscn`, `.tres`, UI art (`.png`, `.svg`), plus `.uid`, `.import` and `.license` files. Limits: 1 MB per image, 1 MB for anything else. Typed GDScript only; no banned APIs. Tests for the HUD go in `tests/hud/`; the runner and naming are documented in `tests/README.md`, which a later task writes.

## Steps

1. Reuse widgets from `widgets/` before adding new ones.
2. Add UI art lines to `art/manifest.json`.
3. Run the checks below, then open a PR using the template, with a screenshot or short GIF.

## Example to copy

`hud/menus/main_menu/main_menu.tscn` and `main_menu.gd`: the main menu with the Play button. Play sends `play_requested(0)` through the `Events` autoload and nothing else: it never calls `flow` and never changes the scene (flow does, on the event). The test is in `tests/gameplay/flow/test_flow.gd` (it presses the button and scans the script). For a panel, copy `hud/panels/player_panel/` (`player_panel.tscn` and `.gd`: the root script gets its numbers through methods, listens to nothing, and styles itself only through theme variations); its container is `hud/panels/panels.gd`, and the tests are `tests/hud/test_panels.gd` and `tests/gameplay/player/test_player_stats.gd`. For the builder, copy `hud/builder/` (tests in `tests/hud/test_builder.gd` and `tests/hud/test_radial_builder.gd`; `tests/hud/test_radial_builder_bags.gd` checks the ring with 0, 1, 2 and 300 made-up cards from `tests/support/fake_cards.gd`; `tests/screenshots/shot_radial_builder.gd` and `shot_radial_bags.gd` show the radial one, a suite test with real wizards and four builders open at once; `tests/screenshots/shot_builder.gd` shows it). For a menu, copy `hud/menus/pause/` (pages of buttons in one UIFocus list, answering only the signals that name the player working it); its test is `tests/hud/test_pause_menu.gd`.

## Validate

```sh
tools/check.sh
ci/build/build.sh --quick --tests
```

## Review questions

Besides the general review:

- Is it readable with 4 players at 1× on a small screen?
- Can it be fully used with a gamepad, and does each panel respond only to its owner?
- Does it reuse the shared theme and widgets?
